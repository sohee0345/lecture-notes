## 🔁 이전 내용 복습

### EDA, 결측치와 데이터 누수

EDA에서는 데이터의 구조, Target 분포, 자료형과 결측치를 확인한다. 모델 성능을 공정하게 평가하려면 test 데이터의 통계나 분포를 전처리 기준 결정과 모델 선택에 사용하지 않아야 한다.

```text
train → 전처리 기준 학습 + 모델 학습
test  → train에서 정한 전처리 적용 + 최종 평가
```

> **핵심:** 전처리 기준을 포함해 데이터로부터 배우는 모든 과정은 train 안에서 이루어져야 한다.

## 3. train과 test 분리

데이터를 먼저 분리하면 EDA와 전처리 과정에서 test 정보를 보게 되는 위험을 줄일 수 있다.

```python
from sklearn.model_selection import train_test_split

seed = 42

train, test = train_test_split(
    df,
    test_size=0.2,
    random_state=seed,
    stratify=df["survived"],
)
```

- `test_size=0.2` → 전체 행의 20%를 test로 사용한다.
- `random_state=seed` → 무작위 분할 결과를 재현한다.
- `stratify` → 분류 Target의 클래스 비율을 train과 test에 비슷하게 유지한다.

8:2나 7:3은 자주 사용하는 비율이지만 데이터가 몇 건 이상이어야 한다는 고정 규칙은 없다. 데이터 크기, 클래스별 표본 수, 평가 결과의 안정성과 검증 전략을 함께 고려해 정한다.

### 3.1 Feature와 Target 분리

```python
x_train = train.drop(args.target_col, axis=1)
y_train = train[args.target_col]

x_test = test.drop(args.target_col, axis=1)
y_test = test[args.target_col]
```

실습 결과는 다음과 같다.

```text

y_train: (426,)
x_test : (143, 30)
y_test : (143,)
```

## 4. train 중심 EDA와 결측치 처리

Target이 분류 문제라면 클래스별 개수와 비율을 확인한다.

```python
train["survived"].value_counts(normalize=True)
```

Titanic train 데이터의 비율은 사망 약 62.4%, 생존 약 37.6%였다. 클래스 비율이 크게 차이 나면 전체 정확도만으로 성능을 판단하기 어려울 수 있다.

### 4.1 결측치 통계는 train에서 계산

```python
age_fill = train["age"].mean()
embarked_fill = train["embarked"].mode().iloc[0]

train["age"] = train["age"].fillna(age_fill)
test["age"] = test["age"].fillna(age_fill)

train["embarked"] = train["embarked"].fillna(embarked_fill)
test["embarked"] = test["embarked"].fillna(embarked_fill)
```

test의 평균이나 최빈값을 따로 계산하면 평가 데이터의 정보가 전처리에 섞인다. train에서 계산한 값을 test에도 동일하게 적용한다. train과 test의 결측치 비율이 서로 다른 것은 무작위 분할에서 자연스럽게 발생할 수 있다.

## 5. 분류와 회귀

문제 유형은 Target의 저장 자료형이 아니라 의미로 판단한다.

| 문제 | Target 의미 | 예시 |
| --- | --- | --- |
| 회귀 | 연속적인 수치 예측 | 집값, 온도 |
| 이진 분류 | 두 클래스 중 하나 예측 | 생존/사망, 양성/음성 |
| 다중 분류 | 세 개 이상 클래스 중 하나 예측 | 꽃 품종, 문서 주제 |

Target이 숫자 0과 1로 저장되어도 클래스 코드라면 회귀가 아니라 분류이다.

## 6. 특성 공학

특성 공학(Feature Engineering)은 기존 데이터에서 모델 학습에 도움이 될 새 Feature를 만들거나 표현을 바꾸는 과정이다.

### 6.1 수치형 특성 생성

```python
for frame in [train, test]:
    frame["family_cnt"] = frame["sibsp"] + frame["parch"]
```

형제·배우자 수와 부모·자녀 수를 더해 가족 수를 만든다. 같은 변환을 train과 test에 적용한다.

### 6.2 범주형 특성 결합

```python
for frame in [train, test]:
    frame["deck"] = frame["deck"].astype(str)
    frame["deck_who"] = frame["deck"] + "_" + frame["who"]
```

test 특성은 반드시 test 컬럼끼리 계산한다. train Series를 test에 대입하면 인덱스가 달라 값이 어긋나거나 결측치가 생길 수 있다.

Feature 수를 행 수의 5% 미만으로 제한하는 고정 규칙은 없다. Feature가 지나치게 많아지면 계산량과 과적합 위험이 커질 수 있으므로 표본 수, 모델과 검증 결과를 기준으로 판단한다.

## 7. 범주형 인코딩

범주형 인코딩은 문자열이나 범주형 값을 모델이 처리할 수 있는 수치 표현으로 바꾸는 과정이다.

### 7.1 One-Hot Encoding

각 범주에 대응하는 컬럼을 만들고 해당 범주이면 1, 아니면 0으로 표현한다.

```text
color = red, blue, green
  ↓
color_red  color_blue  color_green
    1          0           0
```

범주 사이에 임의의 순서를 만들지 않는 장점이 있지만 범주 수가 많으면 컬럼 수와 희소한 0 값이 크게 늘어난다. 클래스 수가 적은 명목형 변수에서는 우선 고려할 수 있으며, 성능은 모델과 데이터에 따라 검증한다.

### 7.2 Ordinal Encoding

순서형 범주를 순서에 맞는 숫자로 바꾼다.

```text
low → 0, medium → 1, high → 2
```

순서가 없는 명목형 변수에 적용하면 모델이 존재하지 않는 크기 관계를 학습할 수 있다.

### 7.3 Target Encoding

각 범주를 그 범주에 속한 train Target의 평균으로 바꾼다. Mean Encoding이라고도 부른다.

```text
범주 A의 Target 평균 → A의 인코딩 값
범주 B의 Target 평균 → B의 인코딩 값
```

Target을 이용하므로 전체 데이터나 test를 사용해 계산하면 데이터 누수가 발생한다. train 안에서도 자기 자신의 Target 정보가 직접 반영되어 과적합되기 쉬우므로 검증 분리를 고려해 계산해야 한다.

## 8. 모델 파라미터와 하이퍼파라미터

- 모델 파라미터 → 학습 과정에서 데이터로부터 결정되는 값
- 하이퍼파라미터 → 학습 전에 사람이 지정하거나 탐색하는 설정값

```python
from sklearn.linear_model import LogisticRegression

model = LogisticRegression(random_state=args.seed)
model.fit(x_train, y_train)
```

로지스틱 회귀는 클래스 확률을 이용하는 분류 모델이다. 실습에서는 최대 반복 횟수에 도달했다는 수렴 경고가 발생했으므로 평가값만 보고 학습이 충분히 완료되었다고 판단하지 않는다.

```python
from sklearn.metrics import accuracy_score

y_pred = model.predict(x_test)
accuracy = accuracy_score(y_test, y_pred)
# 약 0.972
```

`set_config(display="text")`는 scikit-learn 추정기의 표시 방식을 텍스트로 설정한다.

## 전체 흐름

```text
데이터 로드와 컬럼 의미 확인
  ↓
train·test 분리와 랜덤 시드 고정
  ↓
train으로 Target·자료형·결측치 EDA
  ↓
train에서 전처리 기준 계산
  ↓
같은 기준과 특성 생성 규칙을 test에 적용
  ↓
범주 의미에 맞는 인코딩 선택
  ↓
모델과 하이퍼파라미터 설정
  ↓
train으로 학습
  ↓
test로 최종 평가
```

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| train / test | 모델 학습용 데이터 / 최종 평가용 데이터 |
| 랜덤 시드 | 무작위 과정을 재현하기 위한 초기값 |
| 특성 공학 | 기존 컬럼으로 새 Feature를 만드는 과정 |
| 범주형 인코딩 | 범주를 모델이 처리할 수 있는 수치로 표현 |
| 하이퍼파라미터 | 학습 전에 설정하거나 탐색하는 값 |
| 모델 파라미터 | 학습 과정에서 데이터로부터 결정되는 값 |

### 💻 주요 코드

| 코드 | 의미 |
| --- | --- |
| `train_test_split(..., stratify=y)` | 클래스 비율을 고려해 데이터를 분할 |
| `value_counts(normalize=True)` | 클래스별 비율 계산 |
| `train.mean()` / `train.mode()` | train에서 대체 기준 계산 |
| `frame["family_cnt"] = ...` | 기존 컬럼으로 새 특성 생성 |
| `model.fit(x_train, y_train)` | 학습 데이터로 모델 훈련 |
| `model.predict(x_test)` | test Feature의 클래스 예측 |

### ⭐ 오늘의 핵심

- **누수 방지:** 분할 이후의 EDA와 전처리 기준 계산은 train만 사용한다.
- **문제 정의:** Target의 저장 자료형이 아니라 의미와 예측 목적에 따라 분류·회귀를 결정한다.
- **인코딩 선택:** 명목형·순서형과 범주 수, Target 사용 여부에 맞는 인코딩을 선택한다.
