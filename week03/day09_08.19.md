## 🔁 이전 내용 복습

### Docker와 컨테이너

Docker는 프로그램과 실행에 필요한 환경을 컨테이너라는 격리된 단위로 실행하는 도구이다. MySQL을 컨테이너로 실행하면 로컬 PC에 서버를 직접 설치하지 않고도 정해진 버전과 설정을 재현할 수 있다.

```bash
docker compose up -d
docker compose down
```

- `docker compose up -d` → 서비스를 생성하고 백그라운드에서 실행한다.
- `docker compose down` → Compose로 실행한 컨테이너와 네트워크를 중지하고 제거한다.

> **핵심:** Docker로 MySQL 실행 환경을 분리하면 설치와 정리가 쉽고 같은 환경을 다시 만들기 편하다.

## 1. MySQL 실행과 접속

MySQL 서버를 Docker 컨테이너로 실행한 뒤 Docker Desktop에서 컨테이너가 실행 중인지 확인한다. 실습 화면에서는 `server` 컨테이너가 실행 상태로 표시되었다.

DBeaver는 MySQL을 비롯한 데이터베이스에 접속하여 SQL을 작성하고 실행 결과를 확인하는 GUI 도구이다. MySQL 연결 화면에서 서버 주소, 포트, 사용자 이름, 비밀번호를 입력하고 `Test Connection`으로 연결을 검사한다. 로컬 서버의 기본 접속 정보는 보통 `localhost`와 포트 `3306`을 사용한다.

접속 과정은 다음과 같다.

```text
New Connection에서 MySQL 선택
  ↓
Host·Port·Username·Password 입력
  ↓
Test Connection으로 연결 확인
  ↓
연결 저장 후 SQL 편집기 열기
```

공개 키 검색과 관련된 인증 오류가 발생하면 해당 연결의 `Driver properties`에서 `allowPublicKeyRetrieval` 값을 확인한다. 보안 설정과 서버 구성에 따라 필요한 값이 달라질 수 있으므로 신뢰할 수 있는 로컬 실습 환경인지 확인한 뒤 설정한다.

### 1.1 DBeaver에서 SQL 실행하기

- SQL 문장은 세미콜론(`;`)으로 끝낸다.
- 커서를 실행할 문장 안에 놓고 `Ctrl + Enter`를 누르면 해당 문장을 실행할 수 있다.
- 여러 문장을 작성했을 때 세미콜론이 문장의 경계를 구분한다.

```sql
SHOW DATABASES;
USE examplesdb;
SHOW TABLES;
```

- `SHOW DATABASES` → 서버에 있는 데이터베이스 목록을 확인한다.
- `USE` → 이후 SQL이 실행될 데이터베이스를 선택한다.
- `SHOW TABLES` → 선택한 데이터베이스의 테이블 목록을 확인한다.

## 2. 데이터베이스와 테이블 만들기

관계형 데이터베이스의 테이블은 행(row)과 열(column)로 데이터를 저장한다. 행은 하나의 데이터 항목이고, 열은 이름·나이처럼 각 항목이 가져야 할 속성이다. 테이블을 만들 때는 각 열에 저장할 값의 종류와 규칙을 함께 정한다.

### 2.1 데이터베이스 생성과 선택

```sql
CREATE DATABASE IF NOT EXISTS mysql_ddl_practice
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_unicode_ci;

USE mysql_ddl_practice;
```

- `IF NOT EXISTS` → 같은 이름의 데이터베이스가 없을 때만 생성한다.
- `utf8mb4` → 한글과 이모지를 포함한 유니코드 문자를 저장할 수 있는 문자 집합이다.
- `COLLATE` → 문자열을 비교하고 정렬하는 규칙을 지정한다.

### 2.2 테이블 생성·삭제·구조 확인

```sql
DROP TABLE IF EXISTS usertb;

CREATE TABLE usertb (
    id INT AUTO_INCREMENT COMMENT '사용자 식별자',
    name VARCHAR(10) DEFAULT '없음' COMMENT '사용자 이름',
    addr VARCHAR(500) NOT NULL COMMENT '사용자 집주소',
    PRIMARY KEY (id)
) COMMENT = '사용자 테이블';

DESCRIBE usertb;
```

- `CREATE TABLE` → 테이블 이름, 컬럼, 데이터 타입, 제약조건을 정의한다.
- `DROP TABLE` → 테이블의 구조와 데이터를 함께 삭제한다.
- `IF EXISTS` → 대상이 없을 때 발생할 오류를 피한다.
- `COMMENT` → 테이블이나 컬럼의 용도를 설명하는 메타데이터를 남긴다.
- `DESCRIBE` → 컬럼 이름, 타입, NULL 허용 여부, 키와 기본값 등을 확인한다.

> **핵심:** 테이블 생성문은 단순히 저장 공간만 만드는 것이 아니라 저장할 데이터의 형태와 허용 규칙까지 설계한다.

### 2.3 테이블 구조 변경

이미 생성한 테이블의 구조는 `ALTER TABLE`로 바꾼다.

```sql
ALTER TABLE datatype_examples
ADD COLUMN email VARCHAR(120) COMMENT '수강생 이메일';

ALTER TABLE datatype_examples
MODIFY COLUMN memo VARCHAR(500) COMMENT '메모';

ALTER TABLE datatype_examples
DROP COLUMN email;
```

- `ADD COLUMN` → 새 컬럼을 추가한다.
- `MODIFY COLUMN` → 기존 컬럼의 타입, 길이, 속성 등을 변경한다.
- `DROP COLUMN` → 컬럼과 그 컬럼의 데이터를 삭제한다.

## 3. 데이터 타입과 컬럼 제약조건

데이터 타입은 컬럼에 어떤 종류의 값을 저장할지 정하고, 제약조건은 어떤 값까지 허용할지 정한다. 알맞은 타입과 제약조건을 사용하면 잘못된 데이터가 저장되는 일을 데이터베이스 단계에서 막을 수 있다.

### 3.1 주요 MySQL 데이터 타입

| 데이터 타입 | 저장하는 값 | 예시 |
| --- | --- | --- |
| `INT` | 일반적인 정수 | 식별자, 수량 |
| `TINYINT UNSIGNED` | 음수가 없는 작은 정수 | 나이 |
| `DECIMAL(10, 2)` | 전체 10자리, 소수점 이하 2자리의 정확한 수 | 금액, 점수 |
| `VARCHAR(n)` | 최대 `n`문자의 가변 길이 문자열 | 이름, 이메일 |
| `TEXT` | 비교적 긴 문자열 | 메모 |
| `BOOLEAN` | 참 또는 거짓 | 활성 상태 |
| `DATE` | 날짜 | 생년월일, 가입일 |
| `DATETIME` | 날짜와 시간 | 로그인 시각 |
| `ENUM(...)` | 미리 정한 문자열 중 하나 | 난이도, 상태 |
| `JSON` | JSON 형식의 구조화된 값 | 추가 프로필 |

`VARCHAR(20)`의 20은 바이트 수가 아니라 저장 가능한 최대 문자 수를 뜻한다. 다만 실제 저장 공간과 인덱스 제한은 문자 집합에 따른 바이트 수의 영향을 받을 수 있다.

### 3.2 주요 제약조건

```sql
CREATE TABLE students (
    student_id INT AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(120) NOT NULL UNIQUE,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (student_id)
);
```

- `NOT NULL` → 반드시 값이 있어야 한다.
- `UNIQUE` → 중복 값을 허용하지 않는다.
- `DEFAULT` → 값을 생략했을 때 사용할 기본값을 정한다.
- `CHECK` → 값이 만족해야 할 조건을 정한다.
- `PRIMARY KEY` → 각 행을 고유하게 식별하며 중복과 `NULL`을 허용하지 않는다.

`AUTO_INCREMENT`는 새 행을 추가할 때 정수 값을 자동으로 증가시킨다. 기본키와 함께 사용하면 식별자를 직접 입력하지 않아도 된다.

```sql
INSERT INTO usertb (name, addr)
VALUES
    ('홍길동', '서울 강남'),
    ('신사임당', '부산 해운대');
```

실행 결과의 `id`에는 1, 2와 같은 값이 자동으로 부여된다.

## 4. 데이터 추가와 조회

`INSERT`는 테이블에 행을 추가하고, `SELECT`는 저장된 데이터를 조회한다.

```sql
INSERT INTO students (name, email, birth_date, phone)
VALUES
    ('김민준', 'minjun@example.com', '2001-03-12', '010-1111-1111'),
    ('이서연', 'seoyeon@example.com', '2000-07-22', '010-2222-2222');

SELECT *
FROM students;
```

컬럼 목록을 명시한 `INSERT`에서는 목록과 값의 순서가 일치해야 한다. 자동 증가 컬럼이나 기본값을 사용할 컬럼은 목록에서 생략할 수 있다. `SELECT *`는 모든 컬럼을 조회하지만, 필요한 컬럼만 명시하면 결과의 목적이 더 분명해진다.

```sql
SELECT
    id,
    name,
    addr
FROM usertb;
```

명령의 성격에 따라 `CREATE`, `ALTER`, `DROP`은 구조를 정의하는 DDL(Data Definition Language), `INSERT`와 `SELECT`는 데이터를 추가하거나 조회하는 DML(Data Manipulation Language)에 해당한다.

## 5. 테이블 관계와 외래키

관계형 데이터베이스에서는 하나의 큰 테이블에 모든 정보를 반복해서 저장하지 않고, 주제별 테이블로 나눈 뒤 기본키와 외래키로 연결한다. 외래키(`FOREIGN KEY`)는 자식 테이블의 값이 부모 테이블의 기본키를 참조하도록 하여 존재하지 않는 데이터를 가리키지 못하게 한다.

### 5.1 1:N 관계

한 명의 수강생이 여러 수강 신청을 할 수 있다면 `students`와 `enrollments`는 1:N 관계이다. 한 건의 수강 신청에 여러 결제가 연결될 수 있으므로 `enrollments`와 `payments`도 1:N 관계이다.

```text
students 1 ─── N enrollments 1 ─── N payments
```

### 5.2 N:M 관계와 연결 테이블

한 학생은 여러 강의를 신청할 수 있고, 한 강의에도 여러 학생이 참여할 수 있다. 이 N:M 관계는 `enrollments`라는 연결 테이블을 두 개의 1:N 관계로 바꾸어 표현한다.

```text
students 1 ─── N enrollments N ─── 1 courses
```

```sql
CREATE TABLE enrollments (
    enrollment_id INT AUTO_INCREMENT,
    student_id INT NOT NULL,
    course_id INT NOT NULL,
    PRIMARY KEY (enrollment_id),
    UNIQUE KEY uq_enrollments_student_course (student_id, course_id),
    CONSTRAINT fk_enrollments_student
        FOREIGN KEY (student_id) REFERENCES students(student_id)
        ON DELETE CASCADE,
    CONSTRAINT fk_enrollments_course
        FOREIGN KEY (course_id) REFERENCES courses(course_id)
        ON DELETE RESTRICT
);
```

- 복합 `UNIQUE` → 같은 학생이 같은 강의를 중복 신청하지 못하게 한다.
- `ON DELETE CASCADE` → 부모 행을 삭제하면 연결된 자식 행도 함께 삭제한다.
- `ON DELETE RESTRICT` → 참조하는 자식 행이 있으면 부모 행 삭제를 막는다.

외래키가 있는 테이블은 부모 데이터를 먼저 생성한 뒤 자식 데이터를 추가해야 한다. 삭제하거나 테이블을 초기화할 때는 반대로 가장 하위의 자식 테이블부터 처리해야 참조 제약을 위반하지 않는다.

### 5.3 JOIN으로 관계 데이터 조회

나뉜 테이블의 정보는 `JOIN`으로 연결해 한 결과에서 확인한다.

```sql
SELECT
    s.name AS student_name,
    c.title AS course_title,
    e.status,
    e.score,
    p.amount,
    p.method
FROM enrollments e
JOIN students s ON e.student_id = s.student_id
JOIN courses c ON e.course_id = c.course_id
LEFT JOIN payments p ON e.enrollment_id = p.enrollment_id
ORDER BY s.name, c.title;
```

`JOIN`은 양쪽에 대응하는 행이 있는 데이터만 연결하고, `LEFT JOIN`은 왼쪽 테이블의 행을 모두 유지하면서 오른쪽에 대응하는 행이 있으면 함께 보여 준다.

## 전체 흐름

```text
Docker로 MySQL 서버 실행
  ↓
DBeaver에서 MySQL 연결
  ↓
데이터베이스 생성 및 선택
  ↓
데이터 타입과 제약조건을 정해 테이블 설계
  ↓
INSERT로 데이터 추가, SELECT로 조회
  ↓
기본키와 외래키로 테이블 연결
  ↓
JOIN으로 관계가 있는 데이터 조회
```

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| Docker Compose | MySQL 서버를 컨테이너로 실행하고 관리한다. |
| DBeaver | 데이터베이스에 접속하여 SQL을 실행하는 GUI 도구이다. |
| 데이터 타입 | 컬럼에 저장할 값의 종류와 형태를 정한다. |
| 제약조건 | 저장 가능한 값의 규칙을 정해 데이터 무결성을 지킨다. |
| 기본키 | 각 행을 고유하게 식별한다. |
| 외래키 | 다른 테이블의 키를 참조하여 테이블 사이의 관계를 유지한다. |
| 연결 테이블 | N:M 관계를 두 개의 1:N 관계로 풀어 표현한다. |

### 💻 주요 코드

| 코드 | 의미 |
| --- | --- |
| `CREATE DATABASE` | 데이터베이스를 생성한다. |
| `CREATE TABLE` | 컬럼과 제약조건을 정의하여 테이블을 생성한다. |
| `ALTER TABLE` | 기존 테이블의 구조를 변경한다. |
| `DROP TABLE IF EXISTS` | 테이블이 있을 때만 삭제한다. |
| `INSERT INTO` | 테이블에 데이터를 추가한다. |
| `SELECT ... FROM` | 테이블의 데이터를 조회한다. |
| `FOREIGN KEY ... REFERENCES` | 다른 테이블을 참조하는 외래키를 정의한다. |

### ⭐ 오늘의 핵심

- **테이블 설계:** 데이터 타입은 값의 형태를, 제약조건은 허용 규칙을 결정한다.
- **식별과 연결:** 기본키는 한 행을 식별하고 외래키는 여러 테이블의 관계를 유지한다.
- **실행 순서:** 부모 데이터를 먼저 추가하고, 참조 관계를 정리할 때는 자식부터 처리한다.
