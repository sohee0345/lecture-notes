## 1. 공공데이터 CSV 찾기와 불러오기

공공데이터를 활용할 때는 국가통계포털이나 공공데이터포털에서 필요한 자료를 검색한다. 파일로 제공되는 데이터는 CSV로 내려받아 Pandas로 분석할 수 있다.

### 1.1 와일드카드와 glob

와일드카드 `*`는 파일명에서 여러 문자를 대신한다. `*.csv`는 확장자가 `.csv`인 모든 파일에 대응한다.

```python
import glob

csv_files = glob.glob("*.csv")
```

현재 폴더에 `data1.csv`, `data2.csv`, `user.csv`, `test.txt`가 있다면 결과에는 CSV 파일 경로만 들어간다.

```python
["data1.csv", "data2.csv", "user.csv"]
```

### 1.2 CSV 인코딩과 구조 확인

CSV를 읽을 때는 파일에 사용된 문자 인코딩을 맞춰야 한다. 일반적으로 UTF-8을 먼저 사용하고, 문자 디코딩 오류가 발생하면 파일의 실제 인코딩을 확인한다.

```python
import pandas as pd

df = pd.read_csv(
    "data.csv",
    encoding="utf-8",
    dtype={"시점": "object"},
)

df.info()
```

`df.info()`에서는 행 개수, 컬럼 이름, 결측이 아닌 값의 개수, 컬럼별 `dtype` 등을 확인할 수 있다.

```text
RangeIndex: 100 entries, 0 to 99
```

위 결과는 인덱스가 0부터 99까지이고 행이 총 100개라는 뜻이다. CSV를 불러온 직후 원본의 예상 행 수와 비교하면 파일이 정상적으로 읽혔는지 점검할 수 있다.

### 1.3 숫자처럼 보이는 코드값

지역 코드 `01`, `02`, `03`은 숫자처럼 보이지만 크기 계산이 아니라 대상을 구분하는 식별값이다. 숫자형으로 읽으면 앞의 0이 사라질 수 있으므로 문자열로 불러오는 것이 적절하다.

```python
df = pd.read_csv(
    "data.csv",
    dtype={"지역코드": "string"},
)
```

연도·분기 표기, 상품 코드처럼 계산 대상이 아닌 값도 같은 기준으로 판단한다.

## 2. Open API로 데이터 요청하기

Open API는 정해진 주소와 형식으로 요청을 보내면 외부 서비스가 데이터를 반환하는 인터페이스이다. 공공데이터 API는 보통 회원가입, 활용 신청, 승인 확인, 인증키 발급 과정을 거쳐 사용한다.

```text
데이터 검색
  ↓
Open API 활용 신청 및 승인 확인
  ↓
인증키 발급
  ↓
.env에 인증키 저장
  ↓
Python에서 요청 전송
  ↓
상태 코드와 응답 데이터 확인
```

### 2.1 인증키 관리

`.env` 파일:

```dotenv
FOOD_SAFETY_API_KEY="발급받은인증키"
```

인증키 파일이 저장소에 올라가지 않도록 `.gitignore`에도 등록한다.

```gitignore
.env
```

### 2.2 requests로 GET 요청 보내기

```python
import os
import requests
from dotenv import load_dotenv

load_dotenv()

api_key = os.getenv("FOOD_SAFETY_API_KEY")
url = f"http://openapi.foodsafetykorea.go.kr/api/{api_key}/I2570/json/1/5"

response = requests.get(url)
print(response.status_code)
data = response.json()
```

- `requests.get(url)` → URL로 HTTP GET 요청을 보낸다.
- `response.status_code` → 서버가 요청을 어떻게 처리했는지 나타내는 상태 코드이다.
- `response.json()` → JSON 응답 본문을 Python의 딕셔너리나 리스트 구조로 변환한다.

상태 코드 `200`은 요청이 정상적으로 처리되었다는 뜻이다. 상태 코드와 함께 실제 응답 구조도 확인해야 원하는 데이터의 위치를 찾을 수 있다.

## 3. 웹 크롤링과 웹 스크래핑

웹 크롤링은 정해진 규칙에 따라 여러 웹페이지를 탐색하는 활동이고, 웹 스크래핑은 특정 웹페이지에서 원하는 정보를 추출하는 활동이다. 실제 작업에서는 탐색과 추출이 함께 수행되는 경우가 많아 웹 크롤링이라는 표현이 넓은 의미로 사용되기도 한다.

```text
웹페이지 탐색
  ↓
페이지 내용 가져오기
  ↓
HTML 구조 분석
  ↓
필요한 정보 추출 및 저장
```

가격 정보 수집, 시장 조사, 경쟁사 분석, 소셜 미디어 동향 파악 등에 활용할 수 있다. 다만 데이터가 Open API로 제공되지 않는다는 이유만으로 자유롭게 수집할 수 있는 것은 아니다.

### 3.1 수집 전 확인할 사항

- 사이트의 이용약관과 데이터 이용 목적을 확인한다.
- `robots.txt`에 표시된 크롤러 접근 규칙을 확인한다.
- 개인정보나 민감한 정보를 수집하지 않는다.
- 짧은 시간에 많은 요청을 보내 서버에 부담을 주지 않는다.
- 수집한 데이터의 저작권과 상업적 이용 가능 여부를 확인한다.

반복 요청에는 간격을 둔다.

```python
import time

for page in range(1, 6):
    # 페이지 요청과 정보 추출
    time.sleep(1)
```

`time.sleep(1)`은 다음 반복을 실행하기 전에 1초 동안 기다린다.

## 4. 정적 웹페이지와 동적 웹페이지

### 4.1 정적 웹페이지

정적 웹페이지는 서버에 저장된 HTML 파일을 요청에 따라 그대로 전달하는 형태이다. URL로 요청한 응답에 필요한 HTML이 들어 있다면 `requests`로 문서를 받고 BeautifulSoup으로 분석할 수 있다.

### 4.2 동적 웹페이지

동적 웹페이지는 로그인, 입력, 클릭 또는 추가 통신에 따라 내용이 만들어지거나 바뀐다. 브라우저에서 JavaScript가 실행된 뒤 데이터가 나타나는 페이지는 단순 HTTP 요청만으로 원하는 내용을 얻기 어려울 수 있어 Playwright나 Selenium 같은 브라우저 자동화 도구를 사용한다.

| 구분 | 정적 웹페이지 | 동적 웹페이지 |
| --- | --- | --- |
| 내용 생성 | 저장된 문서를 전달 | 입력·클릭·통신 결과에 따라 변경 |
| 기본 수집 방식 | `requests`와 BeautifulSoup | Playwright 또는 Selenium |
| 특징 | 구조가 단순하고 요청 결과를 바로 분석하기 쉬움 | 브라우저 동작과 대기가 필요할 수 있음 |

### 4.3 동기와 비동기

동기 방식은 한 작업의 응답을 기다린 뒤 다음 작업을 진행한다. 비동기 방식은 기다리는 동안 다른 작업을 진행할 수 있도록 실행 흐름을 구성한다. Playwright의 비동기 API에서는 `async`, `await`, `asyncio`를 사용한다.

## 5. requests와 BeautifulSoup

정적 HTML을 수집하는 기본 흐름은 `requests`로 문서를 받고 BeautifulSoup으로 구조를 분석하는 것이다.

```python
import requests
from bs4 import BeautifulSoup

response = requests.get("https://example.com")
soup = BeautifulSoup(response.text, "html.parser")
```

- `response.text` → 응답 본문을 문자열로 읽는다.
- `BeautifulSoup(..., "html.parser")` → HTML 문자열을 탐색할 수 있는 구조로 분석한다.
- `soup` → 태그와 텍스트를 찾는 데 사용하는 BeautifulSoup 객체이다.

BeautifulSoup은 HTML이나 XML 같은 마크업 문서를 분석하는 도구이다. JSON 응답은 `response.json()`으로 Python 자료구조로 변환한다.

## 6. Playwright 비동기 브라우저 자동화

Playwright는 Microsoft에서 만든 브라우저 자동화 도구로 Python, JavaScript, Java, C# 등을 지원한다. 동적 페이지 테스트, 스크래핑, 자동화 작업에 사용할 수 있다.

실습에서는 Chromium을 화면이 보이는 모드로 열고 네이버에 접속한 뒤 로그인 버튼을 찾고 클릭했다.

```python
import asyncio
from playwright.async_api import async_playwright


async def naver_login(playwright):
    browser = await playwright.chromium.launch(headless=False)
    context = await browser.new_context()
    page = await context.new_page()

    try:
        await page.goto("http://www.naver.com")
        await page.wait_for_load_state("networkidle")

        try:
            login_button = await page.wait_for_selector(
                "a.MyView-module__link_login___HpHMW",
                timeout=5000,
            )
            await login_button.click()
        except Exception:
            await page.click("text=로그인")
    except Exception as error:
        print(f"오류 발생: {error}")
        await page.screenshot(path="error_screenshot.png")
    finally:
        await browser.close()


async def main():
    async with async_playwright() as playwright:
        await naver_login(playwright)


if __name__ == "__main__":
    asyncio.run(main())
```

- `headless=False` → 브라우저 화면을 보이게 실행한다.
- BrowserContext → 독립적인 브라우저 세션을 만든다.
- Page → 브라우저의 탭 하나를 나타낸다.
- `await page.goto()` → 페이지 이동이 끝날 때까지 기다린다.
- `wait_for_selector()` → 요소가 나타날 때까지 기다린다.
- `finally` → 성공하거나 오류가 발생해도 브라우저를 닫는다.

> [!WARNING]
> **선택자 변경에 대비하기**
> 페이지의 클래스 이름은 바뀔 수 있으므로 실습에서는 클래스 선택자로 찾지 못할 때 `text=로그인`으로 다시 찾도록 구성했다. 오류가 생기면 스크린샷을 저장해 당시 화면을 확인한다.

### 6.1 Playwright와 Selenium

두 도구 모두 실제 브라우저를 자동화한다. PDF 자료에서는 최신 웹 애플리케이션 자동화와 테스트 속도가 중요할 때 Playwright를, 기존 Selenium 코드와 환경을 유지해야 하거나 폭넓은 레거시 지원이 필요할 때 Selenium을 선택하는 기준을 제시했다.
