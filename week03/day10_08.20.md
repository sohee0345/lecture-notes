### 기본키와 테이블 관계

`PRIMARY KEY`는 각 행을 고유하게 식별하며 중복 값과 `NULL`을 허용하지 않는다. 여러 테이블로 나눈 데이터는 기본키와 이를 참조하는 외래키를 기준으로 연결한다. 이번 수업에서는 이 관계를 실제 조회 결과로 결합하기 위해 `JOIN`을 사용한다.

### uv, 환경 변수, 싱글톤과 `__call__()`

- `uv init` → 새 Python 프로젝트를 초기화한다.
- `uv sync` → `pyproject.toml`과 잠금 파일에 맞춰 프로젝트 환경을 동기화한다.
- `load_dotenv()` → `.env`의 값을 프로세스 환경 변수로 불러온다.
- 싱글톤 → 클래스별 인스턴스를 하나만 생성해 재사용하는 패턴이다.
- `__call__()` → 객체를 함수처럼 호출했을 때 실행되는 매직 메서드이다.

> **핵심:** 이전에 배운 데이터베이스 관계와 Python 객체·환경 관리 방식을 결합해 SQL 조회 기능을 Python 코드로 재사용한다.

## 1. MySQL 컨테이너에서 명령줄 접속

Docker Desktop의 실행 중인 MySQL 컨테이너에서 `Exec` 탭을 열면 컨테이너 내부 셸에 명령을 입력할 수 있다. 실습 화면에서는 `mysql:latest` 이미지의 컨테이너가 호스트의 `3306` 포트와 연결되어 있었다.

```bash
mysql -u root -p
```

- `-u root` → `root` 사용자로 접속한다.
- `-p` → 명령 실행 후 비밀번호를 입력한다.

접속한 뒤 MySQL의 시스템 데이터베이스에서 사용자와 접속 허용 위치를 조회할 수 있다.

```sql
USE mysql;

SELECT Host, User
FROM user;
```

`Host`는 사용자가 접속할 수 있는 호스트 범위를, `User`는 계정 이름을 나타낸다. DBeaver 같은 GUI 없이도 MySQL 명령줄 클라이언트에서 같은 SQL을 실행할 수 있다.

## 2. SELECT 조회문 구성

`classicmodels` 예제 데이터베이스의 고객, 주문, 주문 상세 테이블을 이용해 조회를 연습한다.

```sql
USE classicmodels;
SHOW TABLES;

SELECT
    customerName,
    phone,
    country,
    creditLimit
FROM customers
WHERE country = 'USA'
ORDER BY creditLimit DESC
LIMIT 10;
```

| 절 | 역할 |
| --- | --- |
| `SELECT` | 결과에 표시할 컬럼이나 계산식을 정한다. |
| `FROM` | 데이터를 가져올 테이블을 정한다. |
| `WHERE` | 행 단위의 조건으로 데이터를 거른다. |
| `ORDER BY` | 결과의 정렬 기준을 정한다. |
| `ASC` / `DESC` | 오름차순 또는 내림차순을 지정한다. |
| `LIMIT` | 반환할 행의 수를 제한한다. |

작성 순서와 실제 논리적 처리 순서는 다르다. 기본 조회에서는 먼저 `FROM`에서 대상을 정하고 `WHERE`로 행을 거른 뒤, `SELECT` 결과를 만들고 `ORDER BY`와 `LIMIT`을 적용한다고 이해하면 쉽다.

```text
FROM → WHERE → SELECT → ORDER BY → LIMIT
```

## 3. 집계 함수와 GROUP BY

집계 함수는 여러 행을 하나의 요약 값으로 계산한다. `COUNT()`는 개수를 세고 `SUM()`은 합계를 구한다. 고객별처럼 기준별 요약이 필요할 때는 `GROUP BY`로 같은 값을 가진 행을 묶는다.

### 3.1 주문이 많은 고객 찾기

```sql
SELECT
    customerNumber,
    COUNT(orderNumber) AS order_count
FROM orders
GROUP BY customerNumber
ORDER BY order_count DESC
LIMIT 3;
```

- `GROUP BY customerNumber` → 같은 고객의 주문을 한 그룹으로 묶는다.
- `COUNT(orderNumber)` → 각 고객 그룹의 주문 개수를 센다.
- `AS order_count` → 계산 결과에 의미가 드러나는 별칭을 붙인다.

### 3.2 고객별 총 구매 금액 계산

주문 상세 한 행의 상품 금액은 주문 수량과 개별 가격을 곱해 계산한다.

```sql
SELECT
    orderNumber,
    quantityOrdered * priceEach AS line_total
FROM orderdetails;
```

이 결과를 주문 테이블과 연결한 뒤 고객별로 합산한다.

```sql
SELECT
    o.customerNumber,
    SUM(od.quantityOrdered * od.priceEach) AS customer_total
FROM orders AS o
JOIN orderdetails AS od
    ON o.orderNumber = od.orderNumber
GROUP BY o.customerNumber
ORDER BY customer_total DESC;
```

`SUM()`은 JOIN 결과에서 같은 고객 그룹에 속한 모든 주문 상세 금액을 더한다. `GROUP BY`를 사용할 때 집계하지 않는 조회 컬럼은 그룹 기준과 일치하도록 작성해야 결과의 의미가 분명하다.

## 4. JOIN과 서브쿼리

`JOIN`은 관련된 여러 테이블을 공통 키로 연결한다. 서브쿼리는 다른 SQL문 안에서 먼저 실행할 중간 결과를 만든다.

### 4.1 JOIN과 별칭

```sql
SELECT
    c.customerName,
    c.phone,
    c.country,
    ranked.order_count
FROM customers AS c
JOIN (
    SELECT
        customerNumber,
        COUNT(orderNumber) AS order_count
    FROM orders
    GROUP BY customerNumber
    ORDER BY order_count DESC
    LIMIT 3
) AS ranked
    ON c.customerNumber = ranked.customerNumber;
```

- `c`, `ranked` → 테이블과 서브쿼리 결과의 별칭이다.
- `ON` → 두 결과에서 어떤 값이 같을 때 한 행으로 연결할지 정한다.
- 일반 `JOIN`은 `INNER JOIN`과 같으며 양쪽에 연결되는 행이 있을 때만 결과에 포함한다.

복잡한 조회는 안쪽의 작은 쿼리부터 실행 결과를 확인한 뒤 바깥 쿼리와 연결하면 이해하고 오류를 찾기 쉽다.

### 4.2 총 구매 금액 상위 고객 조회

```sql
SELECT
    c.customerName,
    c.phone,
    c.country,
    c.creditLimit,
    totals.customer_total
FROM customers AS c
JOIN (
    SELECT
        o.customerNumber,
        SUM(od.quantityOrdered * od.priceEach) AS customer_total
    FROM orders AS o
    JOIN orderdetails AS od
        ON o.orderNumber = od.orderNumber
    GROUP BY o.customerNumber
    ORDER BY customer_total DESC
    LIMIT 3
) AS totals
    ON c.customerNumber = totals.customerNumber
ORDER BY totals.customer_total DESC;
```

실행 결과:

| customerName | phone | country | creditLimit | customer_total |
| --- | --- | --- | ---: | ---: |
| Euro+ Shopping Channel | (91) 555 94 44 | Spain | 227600.00 | 820689.54 |
| Mini Gifts Distributors Ltd. | 4155551450 | USA | 210500.00 | 591827.34 |
| Australian Collectors, Co. | 03 9520 4555 | Australia | 117300.00 | 180585.07 |

```text
orderdetails에서 상품별 금액 계산
  ↓
orders와 연결해 고객 번호 확인
  ↓
고객별 금액 합산
  ↓
상위 3명 선택
  ↓
customers와 연결해 고객 정보 조회
```

### 4.3 ERD에서 기본키와 외래키 확인하기

ERD(Entity Relationship Diagram)는 테이블의 컬럼과 키, 테이블 사이의 관계를 그림으로 나타낸다.

![[스크린샷 2026-08-20 212948.png|800]]

이미지에서 노란색 열쇠는 기본키, 분홍색 열쇠는 다른 테이블을 참조하는 외래키를 나타낸다.

- `model_mapping.model_key` → 차량 모델을 식별하는 기본키이다.
- `recall.recall_id` → 리콜 데이터를 식별하는 기본키이다.
- `recall.model_key` → `model_mapping.model_key`를 참조해 리콜 데이터와 표준 차량 모델을 연결한다.
- `new_registration.registration_id` → 신규 등록 데이터를 식별하는 기본키이다.
- `new_registration.model_key` → `model_mapping.model_key`를 참조해 신규 등록 데이터와 표준 차량 모델을 연결한다.

따라서 하나의 표준 차량 모델은 여러 리콜 데이터와 여러 신규 등록 데이터에 연결될 수 있다. `faq` 테이블은 이미지에 다른 테이블과 연결선이 표시되어 있지 않으므로 독립된 테이블로만 확인한다.

### 5.1 `.env`에서 접속 정보 읽기

비밀번호를 코드에 직접 작성하면 저장소에 함께 올라가 노출될 수 있다. 접속 정보는 `.env`에 분리하고 `python-dotenv`로 현재 Python 프로세스의 환경 변수에 불러온다.

```python
import os

from dotenv import load_dotenv

load_dotenv()

DB_CONFIG = {
    "host": os.getenv("DB_HOST"),
    "port": int(os.getenv("DB_PORT", "3306")),
    "user": os.getenv("DB_USER"),
    "password": os.getenv("DB_PASSWORD"),
    "database": os.getenv("DB_NAME"),
}
```

`os`는 운영체제 기능과 환경 변수에 접근하는 Python 표준 라이브러리 모듈이다. `.env`를 만들기만 해서는 `os.getenv()`가 파일을 자동으로 읽지 않으므로 먼저 `load_dotenv()`를 실행해야 한다.

```text
.env → load_dotenv() → 프로세스 환경 변수 → os.getenv()
```

노트북에서 `.env`를 수정했는데 값이 바뀌지 않으면 커널을 다시 시작하여 변경된 설정을 다시 불러온다.

## 6. PyMySQL의 Connection과 Cursor

`pymysql`은 Python 프로그램이 MySQL 서버와 통신할 수 있게 하는 드라이버이다. 연결에는 호스트, 포트, 사용자, 비밀번호, 데이터베이스 이름이 필요하다.

```python
import pymysql

with pymysql.connect(**DB_CONFIG) as conn:
    with conn.cursor() as cur:
        cur.execute("SHOW TABLES;")
        results = cur.fetchall()
```

| 구성 요소 | 역할 |
| --- | --- |
| Connection | Python과 MySQL 서버의 연결 세션을 관리한다. |
| Cursor | 연결을 통해 SQL을 전달하고 조회 결과를 가져온다. |
| `execute()` | SQL문과 필요한 값을 서버에 전달해 실행한다. |
| `fetchall()` | 조회 결과의 남은 행을 모두 가져온다. |

`with`문을 사용하면 블록이 끝날 때 Cursor와 Connection이 정리되어 닫기 작업을 빠뜨릴 가능성이 줄어든다. `DictCursor`를 지정하면 각 결과 행을 컬럼 이름을 키로 가진 딕셔너리로 받을 수 있다.

```python
conn = pymysql.connect(
    **DB_CONFIG,
    charset="utf8mb4",
    cursorclass=pymysql.cursors.DictCursor,
)
```

## 7. MySQLDB 객체로 조회 기능 재사용

연결과 조회 코드를 `connections.py`의 클래스로 분리하면 노트북에서는 SQL과 결과 활용에 집중할 수 있다. 실습에서는 메타클래스 기반 싱글톤과 `__call__()`을 사용했다.

```python
import pymysql


class Singleton(type):
    _instances = {}

    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]


class MySQLDB(metaclass=Singleton):
    def __init__(self, db_config: dict) -> None:
        self.conn = pymysql.connect(
            **db_config,
            charset="utf8mb4",
            cursorclass=pymysql.cursors.DictCursor,
        )

    def __call__(self, query: str) -> list[dict]:
        with self.conn.cursor() as cur:
            cur.execute(query=query)
            return cur.fetchall()
```

```python
from connections import MySQLDB

mysqldb = MySQLDB(DB_CONFIG)
results = mysqldb("SELECT * FROM customers;")
```

`mysqldb(...)`는 `MySQLDB.__call__()`을 실행한다. 그 안에서 Cursor를 만들고 SQL을 실행한 뒤 `DictCursor` 형태의 모든 행을 반환한다.

싱글톤은 같은 프로세스 안에서 연결 객체를 재사용하는 학습 예제이다. 처음 생성한 인스턴스가 계속 반환되므로 같은 클래스를 다시 호출해도 기존 연결 객체를 사용한다.

조회 결과는 Pandas 데이터프레임으로 변환할 수 있다.

```python
import pandas as pd

df = pd.DataFrame(results)
```

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| `WHERE` | 그룹화 전에 행 단위 조건을 적용한다. |
| `GROUP BY` | 같은 기준값을 가진 행을 그룹으로 묶는다. |
| 집계 함수 | 여러 행을 개수나 합계 같은 하나의 값으로 요약한다. |
| `JOIN` | 관련 키를 기준으로 여러 테이블을 연결한다. |
| 서브쿼리 | 다른 SQL문 안에서 중간 결과를 만드는 SQL문이다. |
| Connection | Python과 MySQL 사이의 연결 세션이다. |
| Cursor | SQL을 실행하고 결과를 읽는 객체이다. |
| `.env` | 민감한 설정값을 소스 코드와 분리하는 파일이다. |

### 💻 주요 코드

| 코드 | 의미 |
| --- | --- |
| `ORDER BY ... DESC LIMIT 3` | 큰 값부터 상위 3행을 선택한다. |
| `COUNT(...) ... GROUP BY ...` | 그룹별 행 개수를 계산한다. |
| `SUM(quantityOrdered * priceEach)` | 주문 상품 금액의 합계를 계산한다. |
| `JOIN ... ON ...` | 연결 조건이 맞는 테이블 행을 결합한다. |
| `load_dotenv()` / `os.getenv()` | `.env`를 불러오고 환경 변수 값을 읽는다. |
| `pymysql.connect(**DB_CONFIG)` | MySQL Connection을 생성한다. |
| `cur.execute()` / `cur.fetchall()` | SQL을 실행하고 모든 조회 행을 가져온다. |

### ⭐ 오늘의 핵심

- **단계적 SQL 작성:** 작은 조회와 집계 결과를 먼저 검증한 뒤 JOIN이나 서브쿼리로 확장한다.
- **안전한 설정 관리:** 비밀번호는 코드에 직접 쓰지 않고 `.env`와 환경 변수로 분리한다.
- **역할 분리:** Connection은 연결을, Cursor는 SQL 실행과 결과 조회를 담당한다.
