### Git 브랜치와 웹 크롤링 기본 흐름

Git 브랜치는 작업 흐름을 분리하고 완료된 변경을 병합할 수 있게 한다. `main`은 안정된 코드를 관리하고 `dev`는 개발 중인 변경을 통합하고 테스트하는 용도로 사용할 수 있다.

정적 웹페이지를 수집할 때는 `requests`로 HTML 응답을 받고 BeautifulSoup으로 문서 구조를 분석한다.

```text
URL 요청
  ↓ requests
HTTP 응답
  ↓ response.text
HTML 문자열
  ↓ BeautifulSoup
탐색 가능한 문서 객체
```

> **핵심:** 오늘은 기존 브랜치와 크롤링 개념을 실제 GitHub 설정과 HTML 요소 추출 코드로 확장한다.

## 1. GitHub 인증 정보와 브랜치 보호

### 1.1 Windows 자격 증명 관리자

Windows에서는 GitHub 인증에 사용된 자격 증명을 자격 증명 관리자에서 확인하고 관리할 수 있다. 저장된 계정 정보 때문에 인증 문제가 발생한다면 다음 경로에서 GitHub 관련 항목을 확인한다.

```text
제어판
  ↓
자격 증명 관리자
  ↓
Windows 자격 증명
  ↓
GitHub 관련 자격 증명
```

### 1.2 Branch Protection Rule

GitHub 저장소의 브랜치 보호 규칙은 중요한 브랜치에 직접 변경이 들어가거나 실수로 삭제되는 일을 줄이기 위한 설정이다.

```text
Repository
  ↓
Settings
  ↓
Branches
  ↓
Branch protection rule
```

`Branch name pattern`에 `main`을 지정하면 규칙이 `main` 브랜치에 적용된다. 실습 화면에서는 다음 설정을 확인했다.

![[스크린샷 2026-08-24 092723.png|800]]

- `Require a pull request before merging` → 보호 브랜치에 합치기 전에 Pull Request를 거치게 한다.
- `Require approvals` → 정해진 수의 승인을 받아야 병합할 수 있게 한다.
- `Do not allow bypassing the above settings` → 규칙을 우회하지 못하도록 제한한다.

### 1.3 main과 dev 브랜치

```text
dev에서 개발 변경 통합·테스트
  ↓ Pull Request와 검토
main에 안정된 결과 병합
```

- `main` → 최종적으로 안정된 코드를 관리한다.
- `dev` → 개발 중인 변경을 모아 통합하고 테스트한다.

> **핵심:** 브랜치 이름만 분리하는 것으로 끝나지 않고 보호 규칙과 Pull Request 절차를 함께 사용해야 `main`을 안정적으로 관리할 수 있다.

## 2. requests로 HTTP GET 요청 보내기

`requests`는 Python에서 웹 서버에 HTTP 요청을 보내고 응답을 받는 라이브러리이다.

```python
import requests

response = requests.get(url="https://www.google.com/")
```

```text
Python에서 GET 요청
  ↓
웹 서버에서 요청 처리
  ↓
Response 객체 반환
```

### 2.1 상태 코드

`response.status_code`는 서버의 처리 결과를 숫자로 나타낸다.

| 범위 | 의미 |
| --- | --- |
| `100`번대 | 요청을 처리하는 중임을 알리는 정보 응답 |
| `200`번대 | 요청이 정상 처리됨 |
| `300`번대 | 다른 위치나 자원을 사용하도록 안내하는 리다이렉션 |
| `400`번대 | 요청 형식이나 권한 등 클라이언트 측 오류 |
| `500`번대 | 서버가 요청을 처리하는 과정의 오류 |

실습의 Google, JSONPlaceholder, 네이버 뉴스 요청에서는 상태 코드 `200`을 확인했다.

```python
if 200 <= response.status_code < 300:
    print("성공")
```

### 2.2 Query Parameter

URL의 `?` 뒤에는 서버에 전달할 조회 조건인 쿼리 파라미터를 붙일 수 있다. `requests`에서는 URL 문자열에 직접 이어 붙이지 않고 `params` 딕셔너리로 분리할 수 있다.

```python
response = requests.get(
    url="https://jsonplaceholder.typicode.com/posts",
    params={"userId": "1"},
)
```

```text
기본 URL: https://jsonplaceholder.typicode.com/posts
파라미터: userId=1
완성 요청: .../posts?userId=1
```

서버가 JSON으로 응답하면 `response.json()`으로 Python 자료구조로 변환한다.

```python
titles = [item["title"] for item in response.json()]
```

실습에서는 `userId=1`인 게시물 10개의 제목을 리스트로 추출했다.

## 3. HTTP Header와 개발자 도구

HTTP Header는 요청이나 응답에 관한 부가 정보를 전달한다. 요청 헤더에는 클라이언트 환경이나 이전 페이지 정보 등을 포함할 수 있다.

```python
headers = {
    "User-Agent": "Mozilla/5.0 ...",
    "Referer": "https://news.naver.com/",
}

response = requests.get(
    url="https://news.naver.com/section/105",
    headers=headers,
)
```

- `User-Agent` → 요청을 보내는 브라우저나 실행 환경을 나타낸다.
- `Referer` → 현재 자원을 요청하기 전에 방문한 페이지의 URL을 나타낸다.

브라우저 개발자 도구의 Network 탭에서는 실제 요청 URL, 요청 방식, 상태 코드, 응답 헤더 등을 확인할 수 있다.

![[스크린샷 2026-08-24 113903.png|800]]

이미지에서는 Google 문서 요청이 GET 방식으로 전송되어 `200 OK` 응답을 받은 것을 확인할 수 있다.

## 4. HTML 기본 구조

HTML은 태그를 이용해 웹페이지의 구조를 표현한다.

```html
<ul>
    <li>첫 번째</li>
    <li>두 번째</li>
</ul>
```

| 태그 | 의미 |
| --- | --- |
| `<ul>` | 순서가 없는 목록을 감싼다. |
| `<li>` | 목록의 각 항목을 나타낸다. |
| `<div>` | 여러 요소를 하나의 영역으로 묶는다. |
| `<p>` | 문단을 나타낸다. |
| `<a>` | 다른 주소로 연결되는 링크를 만든다. |
| `<span>` | 문장이나 요소 안의 일부를 묶는다. |

`requests`로 받은 HTML은 `response.text`에서 문자열로 확인할 수 있다.

```python
print(response.text)
```

크롤링에서는 전체 HTML을 그대로 사용하는 것이 아니라 태그, `id`, `class` 등 구조를 확인한 뒤 필요한 요소만 찾는다.

## 5. BeautifulSoup으로 요소 찾기

BeautifulSoup은 HTML 문자열을 분석하여 태그 구조를 탐색할 수 있는 객체로 바꾼다.

```python
from bs4 import BeautifulSoup

soup = BeautifulSoup(response.text, "html.parser")
```

### 5.1 select()

`select()`는 CSS 선택자와 일치하는 모든 요소를 리스트처럼 반환한다.

```python
news_sections = soup.select("#newsct")
price_areas = soup.select("body > div")
```

- `#newsct` → `id="newsct"`인 요소를 찾는다.
- `body > div` → `body`의 바로 아래 자식인 `div` 요소를 찾는다.

> [!warning] `select()` 결과 확인
> 한 요소만 필요할 때도 `select()` 결과에서 인덱스로 접근하기 전에 결과가 있는지 확인해야 한다.

### 5.2 find()와 find_all()

`find()`는 조건에 맞는 첫 요소를, `find_all()`은 모든 요소를 찾는다.

```python
original_prices = price_areas[0].find_all(
    "div",
    class_="o-price",
)
```

Python에서 `class`는 예약어이므로 HTML의 `class` 속성을 지정할 때는 `class_`를 사용한다.

### 5.3 get_text()

`get_text()`는 선택한 요소 내부의 태그를 제외하고 텍스트만 가져온다.

```python
price = original_prices[0].get_text(strip=True)
print(price)
```

실행 결과:

```text
27,000원
```

`find_all()`은 여러 요소를 담은 결과를 반환하므로 각 요소를 선택하거나 반복한 뒤 `get_text()`를 호출한다.

```python
news_list = news_sections[0].find("ul", class_="sa_list")
titles = [item.get_text(strip=True) for item in news_list.find_all("li")]
```

## 6. Selenium 브라우저 자동화

Selenium은 실제 웹 브라우저를 코드로 제어하는 자동화 도구이다. 실습에서는 Chrome을 열고 Selenium 공식 예제 페이지로 이동한 뒤 이름 속성이 `color_input`인 요소를 찾아 클릭했다.

```python
from selenium import webdriver
from selenium.webdriver.common.by import By

driver = webdriver.Chrome()
driver.get("https://www.selenium.dev/selenium/web/linked_image.html")

driver.implicitly_wait(5)

driver.find_element(By.NAME, "color_input").click()
```

- `webdriver.Chrome()` → Chrome을 제어할 WebDriver를 생성한다.
- `driver.get()` → 지정한 URL로 이동한다.
- `implicitly_wait(5)` → 요소를 찾을 때 바로 발견되지 않으면 최대 5초까지 기다리도록 설정한다.
- `find_element(By.NAME, ...)` → `name` 속성으로 첫 번째 요소를 찾는다.
- `click()` → 찾은 요소를 클릭한다.

`implicitly_wait(5)`는 항상 5초 동안 멈추는 명령이 아니라 요소 탐색에 적용되는 최대 대기 시간이다.
