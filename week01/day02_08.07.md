## 1. GitHub 계정과 저장소 준비

### 1.1 2단계 인증

GitHub의 `Settings → Password and authentication → Two-factor authentication`에서 2단계 인증을 설정한다. 인증 앱에 가입한 뒤 GitHub가 보여 주는 QR 코드를 스캔하고 인증 번호를 입력한다.

2단계 인증은 비밀번호 외에 인증 앱의 일회용 번호를 한 번 더 요구하여 계정을 보호한다.

### 1.2 원격 저장소 생성

GitHub 프로필의 `Repositories → New`에서 저장소를 만든다.

- `Repository name` → 저장소 이름을 입력한다. 예: `study_github`
- `Description` → 저장소의 용도를 설명한다.
- `Public` → 누구나 저장소에 접근할 수 있다.
- `Private` → 허용된 사용자만 접근할 수 있다.
- `Add README` → 저장소 안내 문서인 README를 함께 생성한다.

생성 후 `Code`에서 주소를 복사하고 VSCode의 `Git: Clone`으로 `study` 폴더에 복제한다.

## 2. Git의 세 가지 저장 공간

Git은 파일의 상태를 세 공간으로 나누어 관리한다. `.git` 폴더가 있는 프로젝트 전체가 Git 저장소이며, `.git`에는 커밋 이력과 저장소 정보가 보관된다.

### 2.1 Working Directory

실제 프로젝트 파일을 수정하거나 새 파일을 만드는 작업 공간이다. 파일을 변경하면 `Modified` 상태가 된다. `.git` 폴더가 포함된 프로젝트 전체를 Git 저장소라고 한다.

### 2.2 Staging Area

커밋할 파일을 임시로 모아 두는 공간이다.

- `Changes` → 변경되었지만 아직 Stage하지 않은 파일
- `Staged Changes` → 다음 Commit에 포함된 파일

### 2.3 Repository

Commit된 변경 이력이 `.git` 디렉토리에 저장되는 공간이다. 파일은 Commit 후에 `Committed` 상태가 된다.

``` text
Working Directory
  ↓ git add
Staging Area
  ↓ git commit
Git Directory(.git)
```

> **핵심:** `git add`는 커밋 대상을 고르고, `git commit`은 선택한 변경을 로컬 저장소의 이력으로 남긴다.

### 2.4 Git Graph

Git Graph 확장 프로그램은 커밋과 브랜치 흐름을 그래프로 보여 준다.

커밋 후 그래프를 확인하면 새 커밋이 어느 브랜치에 기록되었는지 살펴볼 수 있다.

## 3. 로컬 저장소와 GitHub 동기화

`origin`은 일반적으로 복제한 GitHub 원격 저장소를 가리키는 이름이다. 로컬 커밋과 원격 저장소의 커밋 수가 다르면 두 저장소 사이에 차이가 생긴다.

- `push` → 로컬 커밋을 GitHub 원격 저장소로 전송한다.
- `pull` → GitHub의 변경 내용을 로컬 저장소로 가져와 반영한다.
- `origin/main` → 원격 저장소 `origin`의 `main` 브랜치를 로컬에서 추적하는 이름이다.

협업 중에는 다른 사람이 먼저 올린 변경이 있을 수 있으므로 원격 변경을 확인하고 통합한 뒤 자신의 커밋을 push한다.

``` text
GitHub 변경 확인
  ↓ pull로 로컬에 반영
로컬 작업·커밋
  ↓ push
GitHub에 커밋 반영
```

> **핵심:** 커밋은 먼저 로컬 저장소에 기록되며, GitHub에 반영하려면 별도로 push해야 한다.

## 4. Branch와 Merge

Branch는 여러 개발자가 서로 다른 작업을 독립적으로 진행하게 해준다. 작업이 완료되면 `merge`로 한 브랜치의 변경을 다른 브랜치에 합친다.

### 4.1 브랜치 역할

수업에서 사용한 흐름은 다음과 같다.

| 브랜치       | 역할                        |
| --------- | ------------------------- |
| `main`    | 서비스 배포에 사용하는 안정된 코드 관리    |
| `develop` | feature에서 개발한 내용을 합치고 테스트 |
| `feature` | 기능별 개발 작업 수행              |
| `release` | 배포 전 실제 데이터로 QA 및 배포 테스트  |
| `hotfix`  | 운영 중 발생한 오류를 빠르게 수정       |

``` text
main
  ↓
develop
  ↓
feature → 개발 완료 → merge → develop
                              ↓
                           release
                              ↓
                            main

운영 중 긴급 오류: main → hotfix → 수정 → merge
```

병합할 때는 현재 선택한 브랜치가 변경을 받아들이는 대상이다.
예를 들어 `develop`에 `feature`의 변경을 합치려면 `develop`으로 이동한 뒤 `feature`를 merge한다.
개발이 끝난 `feature` 브랜치는 삭제하고 `develop`과 `main`은 유지한다.

GitHub 저장소 자체를 삭제하려면 저장소의 `Settings → Delete this repository`를 사용한다.

> **핵심:** 브랜치를 만들 때 기준 브랜치를 확인하고, 병합할 때는 현재 브랜치와 가져올 브랜치를 구분해야 한다.

## 5. Python 가상환경과 의존성

가상환경은 프로젝트마다 Python과 패키지 구성을 분리하는 공간이다. 저장소 하나를 하나의 프로젝트 단위로 열고, 프로젝트 안에 `.venv`를 만들어 사용한다.

### 5.1 venv와 pip 방식

`requirements.txt`에 필요한 패키지 이름을 한 줄씩 작성한다.

``` text
jupyter
pandas
seaborn
```

PowerShell 터미널에서 다음 순서로 환경을 구성한다.

``` powershell
py --version
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install --upgrade pip
pip install -r .\requirements.txt
deactivate
```

- `py -m venv .venv` → Python의 `venv` 모듈을 실행해 `.venv` 가상환경을 만든다.
- `-m` → 지정한 Python 모듈을 실행하는 옵션이다.
- `Activate.ps1` → PowerShell에서 가상환경을 활성화한다.
- `pip install -r` → 파일에 적힌 패키지를 한꺼번에 설치한다.
- `deactivate` → 현재 가상환경을 비활성화한다.

### 5.2 uv 방식

``` powershell
uv init --name venv-uv --python 3.12
uv add jupyter pandas seaborn
.\.venv\Scripts\Activate.ps1
deactivate
uv sync
```

- `uv init` → uv 프로젝트를 초기화하고 사용할 Python 버전을 지정한다.
- `uv add` → 패키지를 프로젝트 의존성에 추가하고 환경에 설치한다.
- `pyproject.toml` → 프로젝트 정보와 `jupyter`, `pandas`, `seaborn` 같은 의존성을 기록한다.
- `uv sync` → 프로젝트 설정에 맞게 가상환경과 패키지를 다시 맞춘다.

> **핵심:** 가상환경은 프로젝트 간 패키지 충돌을 막으며, 의존성 파일을 남기면 같은 환경을 다시 만들 수 있다.

## 6. Jupyter Notebook과 Python 기초

Jupyter Notebook 파일은 `.ipynb` 확장자를 사용한다. VSCode에 Jupyter 확장 프로그램을 설치하고 노트북을 만든 뒤 실행할 Python 커널을 선택한다. 셀은 `Shift+Enter`로 실행한다.

### 6.1 변수

변수는 값을 저장하는 이름이며 새로운 값을 다시 대입할 수 있다.

``` python
name = "홍길동"
name
```

실행 결과:

``` text
'홍길동'
```

``` python
name = "신사임당"
name
```

실행 결과:

``` text
'신사임당'
```

### 6.2 상수 관례와 Enum

Python에서는 일반적인 변수의 값 변경을 언어가 막지 않는다. 변경하지 않을 값은 대문자 이름으로 작성해 상수라는 의도를 나타낸다.

``` python
PI = 3.14
PI = "홍길동"
```

위 코드는 오류 없이 실행되므로 대문자 표기는 강제 규칙이 아니라 개발자 사이의 관례이다. 변경이 제한된 값의 집합이 필요하면 `enum.Enum`을 사용할 수 있다.

``` python
import enum

class RAINBOW(enum.Enum):
    RED = "빨강"
    ORANGE = "주황"
    YELLOW = "노랑"
    GREEN = "초록"
    BLUE = "파랑"
    NAVY = "남색"
    PURPLE = "보라"

RAINBOW.RED.value
```

실행 결과:

``` text
'빨강'
```

`RAINBOW.RED.value = "블랙"`처럼 멤버 값을 바꾸려고 하면 `AttributeError`가 발생한다.

### 6.3 Python 파일 실행

실습 파일에서는 `pandas`와 `seaborn`을 가져온 뒤 문자열을 출력했다.

``` python
import pandas as pd
import seaborn as sns

print("Hello World")
```

실행 결과:

``` text
Hello World
```

커널 동작에 문제가 있으면 VSCode 명령 팔레트에서 `Python Debugger: Clear Cache and Reload Window`를 실행해 창을 다시 불러올 수 있다.
