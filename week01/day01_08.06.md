# 08/06 · 1일차 --- Windows 개발 환경 구성

## 1. 개발 도구 설치 순서

첫 수업에서는 Git과 Python을 설치하고, Visual Studio Code(VSCode)를 중심으로 개발할 수 있도록 Windows 환경을 구성한다.
이후 Python 버전과 패키지를 관리하는 `uv`, Linux 환경을 제공하는 WSL 2, 컨테이너 실행에 사용하는 Docker까지 준비한다.

설치 과정에서는 프로그램을 설치하는 것만큼 명령어로 버전을 확인하고 설정이 제대로 적용되었는지 검증하는 과정이 중요하다.

> **핵심:** 도구를 설치한 뒤에는 터미널에서 버전이나 설정을 조회하여 정상 설치 여부를 반드시 확인한다.

## 2. Git 설치와 초기 설정

Git은 파일의 변경 이력을 관리하고 GitHub의 원격 저장소와 협업할 때 사용하는 버전 관리 도구이다.
설치 후 터미널에서 버전을 확인하고, 커밋 작성자를 구분할 수 있도록 사용자 이름과 이메일을 등록한다.

``` powershell
git --version
git config --global user.name "GitHub 아이디"
git config --global user.email "이메일"
git config --list
```

- `git --version` → 설치된 Git의 버전을 확인한다.
- `git config --global user.name` → 현재 Windows 사용자 계정에서 사용할 Git 작성자 이름을 등록한다.
- `git config --global user.email` → Git 작성자 이메일을 등록한다.
- `git config --list` → 저장된 Git 설정을 확인한다.

### 2.1 GitHub 강의 자료 복제

GitHub 저장소의 내용을 내려받아 Git 저장소로 만드는 작업을 `Clone`이라고 한다.

``` text
GitHub 저장소에서 Code 선택
  ↓
저장소 주소 복사
  ↓
VSCode에서 Ctrl+Shift+P
  ↓
Git: Clone 실행 후 주소 입력
  ↓
C:\dev\course 아래에 저장
```

`Ctrl+Shift+P`는 VSCode의 명령 팔레트를 여는 단축키이다. 명령 팔레트에서 `Git: Clone`을 선택하면 복사한 저장소 주소를 이용해 강의 자료를 내려받을 수 있다.

> **핵심:** Git 사용자 정보는 커밋의 작성자 기록에 사용되며, `clone`은 GitHub 저장소를 로컬 컴퓨터로 복제하는 작업이다.

## 3. Python과 VSCode 설치

### 3.1 Python 설치와 PATH 설정

Python 설치 화면에서는 `Add Python to PATH` 옵션을 선택한다. PATH에 Python의 실행 경로가 등록되어야 현재 폴더와 관계없이 터미널에서 `python` 명령을 실행할 수 있다.

``` powershell
python --version
```

버전 번호가 `3.13.15`라면 `3`은 메이저 버전, `13`은 마이너 버전, `15`는 패치 버전이다. 설치 후 실제 출력된 버전 번호를 확인해 Python이 정상적으로 인식되는지 검증한다.

### 3.2 VSCode와 확장 프로그램

VSCode를 설치한 뒤 수업에 필요한 확장 프로그램을 추가한다.

- `Python` → Python 코드 작성과 실행을 지원한다.
- `Git Graph` → Git의 브랜치와 커밋 흐름을 그래프로 확인한다.
- `Material Icon Theme` → 파일과 폴더 종류를 아이콘으로 구분하기 쉽게 만든다.
- `vscode-pdf` → VSCode 안에서 PDF 파일을 확인한다.

개발자용 글꼴로 D2Coding을 설치한 뒤 VSCode 설정의 `Font Family`에 `D2Coding ligature`를 앞쪽에 지정한다. 합자 기능을 사용하려면 `settings.json`에서 `fontLigatures`을 `true`로 변경하여 글꼴 합자 설정을 활성화한다.

``` json
VSCode → File → Preferences → Settings
  ↓
font 검색
  ↓
Font Family 맨 앞에 D2Coding ligature 입력
  ↓
Font Ligatures → Edit in settings.json
  ↓
false를 true로 변경

{
  "editor.fontLigatures": true
}
```

> **핵심:** Python은 PATH 등록 여부를 확인하고, VSCode는 확장 프로그램과 글꼴을 추가해 코드 작성 환경을 완성한다.

## 4. 작업 폴더 구성

C 드라이브에 `dev` 폴더를 만들고 자료의 성격에 따라 하위 폴더를 구분한다.

``` text
C:\dev
├─ course   강의 자료
├─ study    개인 학습 및 작업 파일
└─ project  프로젝트 파일
```

파일 이름 뒤의 `.py`, `.md`, `.pdf`와 같은 부분은 확장자이다. 확장자는 파일의 형식과 용도를 구분하는 데 사용된다. 숨김 파일이나 폴더가 필요할 때는 파일 탐색기의 `보기 → 표시 → 숨긴 항목`을 활성화한다.

## 5. PowerShell 실행 정책

PowerShell 실행 정책은 스크립트를 실행할 수 있는 조건을 제어한다. 관리자 권한으로 PowerShell을 열고 현재 정책을 확인한 뒤 `RemoteSigned`로 변경한다.

``` powershell
Get-ExecutionPolicy
Set-ExecutionPolicy RemoteSigned
Get-ExecutionPolicy
```

변경 여부를 묻는 메시지가 나타나면 `Y`를 입력한다. 변경 후 다시 `Get-ExecutionPolicy`를 실행하여 설정이 적용되었는지 확인한다. 화면을 정리할 때는 `Clear`를 사용할 수 있다.

> **핵심:** 설정을 바꾸기 전과 후에 실행 정책을 조회하여 실제 적용 여부를 확인한다.

## 6. uv로 Python 버전 관리

`uv`는 Python 개발 환경에서 Python 버전과 패키지를 편리하게 관리하는 도구이다. 공식 설치 안내의 Windows 명령을 VSCode 터미널에서 실행한 뒤 버전을 확인한다.

``` powershell
uv --version
uv python list
uv python install 3.12
uv python list
```

- `uv --version` → uv가 정상적으로 설치되었는지 확인한다.
- `uv python list` → 사용할 수 있거나 설치된 Python 버전을 확인한다.
- `uv python install 3.12` → Python 3.12 버전을 설치한다.

설치 명령을 실행한 뒤 목록을 다시 조회하면 Python 3.12의 설치 여부를 검증할 수 있다.

## 7. WSL 2와 Docker

### 7.1 WSL 2 설치

WSL(Windows Subsystem for Linux)은 Windows에서 Linux 실행 환경을 사용할 수 있게 해주는 기능이다. PowerShell에서 WSL을 설치한 뒤 컴퓨터를 재부팅한다.

``` powershell
wsl --install
wsl --version
wsl --set-default-version 2
```

- `wsl --install` → WSL을 설치한다.
- `wsl --version` → 설치된 WSL의 버전을 확인한다.
- `wsl --set-default-version 2` → 새 Linux 배포판의 기본 WSL 버전을 2로 지정한다.

### 7.2 Docker 설치와 오류 확인

Windows용 Docker Desktop을 설치한다. 실행 과정에서 WSL 관련 오류가 발생하면 다음 항목을 차례로 확인한다.

``` powershell
wsl --update
wsl --install
```

제어판의 `Windows 기능 켜기/끄기`에서 `Linux용 Windows 하위 시스템`이 활성화되어 있는지 확인하고, 필요한 작업을 마친 뒤 컴퓨터를 재부팅한다.

> **핵심:** Windows에서 Docker를 사용할 때는 WSL이 설치되어 있고 최신 상태인지 함께 확인한다.
