## 🔁 이전 내용 복습

### 앙상블 모델 비교

앙상블 학습은 여러 모델의 예측을 결합해 일반화 성능을 높이는 방법이다.
XGBoost, LightGBM, CatBoost는 모두 부스팅 계열 모델이지만 범주형 특성 처리 방식과 트리 성장 전략 등이 다르므로 같은 데이터와 평가 기준으로 비교해야 한다.

### 검증 데이터와 테스트 데이터의 역할

모델을 선택할 때는 훈련 데이터 내부의 검증 세트나 교차검증 점수를 사용하고, 테스트 데이터는 선택이 끝난 모델의 최종 성능을 확인하는 데 한 번만 사용한다.
ROC-AUC를 계산할 때는 예측 클래스가 아니라 양성 클래스의 예측 확률 또는 결정 점수를 전달해야 한다.

> **핵심:** 모델 선택용 검증 데이터와 최종 평가용 테스트 데이터의 역할을 분리해야 성능을 공정하게 측정할 수 있다.

## 1. 차원의 저주

### 1.1 차원의 저주란

차원의 저주(Curse of Dimensionality)는 특성 수가 늘어날수록 데이터가 고차원 공간에 희박하게 퍼져, 제한된 샘플만으로는 의미 있는 패턴을 학습하기 어려워지는 현상이다. 차원이 하나 늘 때마다 공간의 크기는 매우 빠르게 커지므로 데이터 수가 그대로라면 샘플 사이의 거리도 전반적으로 멀어지고 가까운 이웃의 의미가 약해질 수 있다.

### 1.2 거리 기반 알고리즘에 미치는 영향

KNN처럼 샘플 사이의 거리를 직접 사용하는 알고리즘은 이 문제의 영향을 특히 크게 받는다. 불필요한 특성이나 지나치게 많은 인코딩 특성이 추가되면 훈련 데이터 주변에서는 예측할 수 있어도 새로운 데이터로 일반화하는 성능이 떨어질 수 있다.

### 1.3 원-핫 인코딩과 KNN 실습

실습에서는 2개 특성을 가진 데이터에 `OneHotEncoder`를 적용해 52차원으로 만든 뒤 KNN을 비교했다.

| 데이터 | 특성 수 | 훈련 정확도 | 테스트 정확도 |
| --- | ---: | ---: | ---: |
| 원본 | 2 | 0.947 | 0.857 |
| 원-핫 인코딩 후 | 52 | 0.895 | 0.429 |

> [!note] 결과 해석
> 이 결과는 수치형 연속값을 각각 별도 범주처럼 인코딩하면서 차원이 크게 늘고, 테스트에서 처음 보는 값과의 거리 관계가 유용하지 않게 된 사례다. 단순히 특성 수를 늘리는 것이 더 많은 정보를 뜻하지는 않는다.

### 1.4 차원의 저주에 대응하는 방법

차원의 저주에 대응하는 대표적인 방법은 다음과 같다.

- 의미 없는 특성을 제거하는 특성 선택
- 여러 특성의 정보를 적은 수의 새 특성으로 압축하는 차원 축소
- 고차원 공간을 충분히 채울 수 있도록 데이터 추가 수집
- 모델 특성에 맞는 인코딩과 규제 사용

## 2. PCA

### 2.1 PCA의 원리

주성분 분석(Principal Component Analysis, PCA)은 데이터가 가장 크게 퍼져 있는 방향을 찾아 서로 직교하는 새로운 축인 주성분으로 데이터를 표현한다. 첫 번째 주성분은 분산을 가장 많이 보존하는 방향이고, 다음 주성분은 앞선 주성분과 직교하면서 남은 분산을 가장 많이 보존하는 방향이다.

### 2.2 주요 개념

PCA는 공분산 행렬의 고유벡터와 고유값으로 이해할 수 있다.

| 개념 | 의미 |
| --- | --- |
| `고유벡터` | 데이터가 퍼진 주요 방향을 나타낸다. |
| `고유값` | 해당 방향이 담고 있는 분산의 크기를 나타낸다. |
| `explained_variance_ratio_` | 각 주성분이 원래 데이터의 분산을 얼마나 설명하는지 보여준다. |
| `n_components` | 남길 주성분의 수를 정한다. |

### 2.3 PCA 적용

```python
from sklearn.decomposition import PCA

pca = PCA(n_components=15)
reduced = pca.fit_transform(sparse_features)
explained_ratio = pca.explained_variance_ratio_.sum()
```

### 2.4 Titanic 실습 결과

Titanic의 원-핫 인코딩 특성 330개를 PCA로 압축하고 `age`, `fare`와 결합해 KNN의 5겹 교차검증 ROC-AUC를 비교한 결과는 다음과 같다.

| 구성 | 최종 특성 수 | 설명 분산 비율 | 평균 ROC-AUC |
| --- | ---: | ---: | ---: |
| 축소 전 | 332 | - | 0.816 |
| 주성분 2개 | 4 | 0.303 | 0.797 |
| 주성분 15개 | 17 | 0.736 | 0.826 |

> [!note] 결과 해석
> 주성분을 2개만 남기면 정보 손실로 성능이 낮아졌고, 15개를 남긴 경우에는 차원을 크게 줄이면서 실습 기준 성능이 소폭 높아졌다. 적절한 주성분 수는 설명 분산 비율과 검증 성능을 함께 보고 결정해야 한다.

> **핵심:** PCA의 목적은 차원을 무조건 최소화하는 것이 아니라, 중요한 분산을 보존하면서 불필요한 차원을 줄이는 것이다.

## 3. SVD와 Truncated SVD

### 3.1 SVD의 원리

특이값 분해(Singular Value Decomposition, SVD)는 $m \times n$ 행렬 $A$를 다음과 같이 분해한다.

$$A=U\Sigma V^T$$

- $U$: 왼쪽 특이벡터로 이루어진 직교 행렬
- $\Sigma$: 특이값이 큰 순서로 놓인 대각 형태의 행렬
- $V^T$: 오른쪽 특이벡터 행렬의 전치

### 3.2 Truncated SVD

모든 특이값을 사용하면 원래 행렬을 복원할 수 있다. Truncated SVD는 큰 특이값과 그에 대응하는 벡터만 남겨 원래 행렬의 주요 구조를 저차원으로 근사한다. 평균 중심화를 요구하는 PCA와 달리 희소 행렬을 그대로 다룰 수 있어 원-핫 인코딩이나 문서-단어 행렬에 자주 사용한다.

```python
from sklearn.decomposition import TruncatedSVD

svd = TruncatedSVD(n_components=15, random_state=42)
reduced = svd.fit_transform(sparse_features)
explained_ratio = svd.explained_variance_ratio_.sum()
```

### 3.3 Titanic 실습 결과

| 구성 | 최종 특성 수 | 설명 분산 비율 | 평균 ROC-AUC |
| --- | ---: | ---: | ---: |
| 축소 전 | 332 | - | 0.816 |
| 성분 2개 | 4 | 0.212 | 0.796 |
| 성분 15개 | 17 | 0.726 | 0.826 |

> [!note] 결과 해석
> 실습에서는 15개 성분이 2개 성분보다 원래 정보와 검증 성능을 더 잘 보존했다.

## 4. NMF

### 4.1 NMF의 원리

비음수 행렬 분해(Non-negative Matrix Factorization, NMF)는 모든 원소가 0 이상인 행렬 $X$를 두 비음수 행렬 $W$, $H$의 곱으로 근사한다.

$$X \approx WH$$

$W$는 각 샘플이 잠재 성분을 얼마나 포함하는지 나타내고, $H$는 각 잠재 성분이 원래 특성을 어떤 비율로 조합하는지 나타낸다.
결과의 값도 음수가 아니므로 이미지의 픽셀 강도나 단어 빈도처럼 양의 성분을 더해서 설명하기 자연스러운 데이터에서 해석하기 좋다.

```python
from sklearn.decomposition import NMF

nmf = NMF(n_components=5, max_iter=500, random_state=42)
reduced = nmf.fit_transform(non_negative_features)
components = nmf.components_
```

### 4.2 입력 조건과 수렴

> [!warning] NMF 사용 시 주의
> NMF는 입력에 음수가 있으면 사용할 수 없고, 반복 최적화가 충분히 수렴하지 않으면 `ConvergenceWarning`이 발생할 수 있다. 이때는 데이터와 초기화 방법을 점검하고 `max_iter`를 조정한다.

### 4.3 Titanic 실습 결과

> [!example] ROC-AUC 비교
> - 축소 전: 약 `0.816`
> - NMF 성분 5개: 약 `0.720`
> - NMF 성분 250개: 약 `0.703`

이는 차원 축소 방법과 성분 수가 데이터 구조 및 모델에 맞지 않으면 성능이 오히려 떨어질 수 있음을 보여준다.

## 5. 앙상블 모델링과 모듈화

### 5.1 Titanic 전처리와 LightGBM

Titanic 데이터에서 중복 의미를 가진 `class`, `embark_town`, `alive`를 제외하고, 타깃 클래스 비율을 유지하도록 훈련·테스트 데이터를 분리했다. 훈련 데이터의 중복 행을 제거한 뒤 결측치는 훈련 데이터에서 구한 평균 또는 최빈값으로 채웠다.

```python
train, test = train_test_split(
    df,
    stratify=df["survived"],
    random_state=42,
)

for col in train.columns[train.isnull().any()]:
    if pd.api.types.is_numeric_dtype(train[col]):
        value = train[col].mean()
    else:
        value = train[col].mode().iloc[0]
    train[col] = train[col].fillna(value)
    test[col] = test[col].fillna(value)
```

LightGBM이 범주형 특성을 인식하도록 해당 열을 `category` 타입으로 변환했다.

> [!warning] LightGBM 결과 점검
> 단일 LightGBM의 재현율은 훈련 데이터 약 `0.919`, 테스트 데이터 약 `0.674`였다. 두 점수의 차이가 크므로 모델 복잡도, 하이퍼파라미터, 검증 방식 등을 점검할 필요가 있다.

### 5.2 반복 작업의 모듈화

공통 코드는 역할에 따라 나누었다.

| 모듈 | 역할 |
| --- | --- |
| `utils.py` | 난수 고정과 타깃 비율을 유지한 데이터 분할 |
| `evaluations.py` | ROC-AUC와 F1 Score 계산 |
| `evaluation_plots.py` | 정규화 혼동행렬 시각화 |
| `modeling.py` | XGBoost·LightGBM·CatBoost 학습, 평가, 예측과 특성 중요도 시각화 |

`Modeling.__init__()`은 학습 특성, 타깃, 평가 함수와 범주형 열 정보를 인스턴스 속성으로 초기화하고 입력 데이터의 결측치와 길이를 검사한다. `fit_evaluation()`은 여러 부스팅 모델을 같은 흐름으로 학습하고 비교하며, `predict_by_best_model()`은 선택한 모델로 예측한다.

### 5.3 공정한 모델 비교 흐름

모델 비교를 공정하게 하려면 다음 흐름을 사용한다.

```text
훈련 데이터
  ↓
교차검증 또는 훈련/검증 분리
  ↓
검증 ROC-AUC로 모델과 설정 선택
  ↓
선택한 모델을 훈련 데이터로 재학습
  ↓
테스트 데이터로 최종 평가
```

ROC-AUC는 `predict_proba(X)[:, 1]`처럼 연속적인 예측 점수로 계산한다. 모델 비교 결과로 얻은 CatBoost의 훈련 점수 약 0.839와 테스트 점수 약 0.788은 실습 실행 결과이지만, 테스트 데이터로 모델을 선택한 값이므로 최종 일반화 성능으로 확정해서는 안 된다.

### 5.4 특성 중요도 시각화

특성 중요도 그래프는 모델별 함수를 하나의 `Enum`에 묶어 모델 유형에 맞는 시각화 함수를 선택했다. 특성 중요도는 모델이 예측 과정에서 특성을 활용한 정도를 나타낼 뿐 인과관계를 의미하지 않는다.

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| `차원의 저주` | 차원이 늘면서 데이터가 희박해지고 학습에 더 많은 샘플이 필요해지는 현상 |
| `PCA` | 분산을 많이 보존하는 직교 방향으로 데이터를 투영하는 차원 축소 방법 |
| `Truncated SVD` | 큰 특이값에 해당하는 성분만 남겨 행렬을 저차원으로 근사하는 방법 |
| `NMF` | 비음수 행렬을 비음수 잠재 성분의 곱으로 근사하는 방법 |
| `모듈화` | 데이터 처리, 학습, 평가, 시각화 책임을 재사용 가능한 단위로 분리하는 설계 |

### 💻 주요 코드

| 코드 | 의미 |
| --- | --- |
| `PCA(n_components=n)` | 남길 주성분 수를 지정해 PCA 생성 |
| `TruncatedSVD(n_components=n)` | 희소 행렬에 사용할 저차원 SVD 생성 |
| `NMF(n_components=n)` | 비음수 잠재 성분 수를 지정해 NMF 생성 |
| `fit_transform()` | 변환 기준을 학습하고 데이터를 저차원으로 변환 |
| `predict_proba()[:, 1]` | ROC-AUC 계산에 사용할 양성 클래스 예측 확률 반환 |

### ⭐ 오늘의 핵심

- 차원이 늘면 정보가 증가할 수도 있지만, 불필요한 차원은 거리의 의미와 일반화 성능을 떨어뜨릴 수 있다.
- 차원 축소 성분 수는 설명 분산 비율만이 아니라 최종 모델의 검증 성능까지 함께 보고 선택한다.
- PCA, Truncated SVD, NMF는 전제와 결과의 성질이 다르므로 데이터 형태와 목적에 맞춰 선택한다.
- 반복되는 전처리·학습·평가·시각화 코드는 역할별로 모듈화하면 일관성과 재사용성이 높아진다.
- 모델 선택은 검증 데이터로 수행하고 테스트 데이터는 최종 평가에만 사용한다.
