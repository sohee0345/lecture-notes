### 모듈·패키지와 Streamlit 위젯

기능을 Python 파일과 폴더로 나누면 `import`로 필요한 함수와 값을 가져와 재사용할 수 있다. Streamlit에서는 입력 위젯의 반환값을 변수에 저장하고 조건문과 연결해 사용자와 상호작용하는 화면을 만든다.

``` python
from common.ai import get_response

user_input = st.text_input("메시지를 입력하세요.")
```

> **핵심:** 이전에 배운 모듈 분리와 Streamlit 입력 방식을 결합해 여러 파일로 구성된 채팅 앱을 만든다.

------------------------------------------------------------------------

## 1. 역할에 따른 모듈화

모듈화는 모든 코드를 한 파일에 작성하지 않고 기능과 역할에 따라 여러 파일로 나누어 관리하는 것이다. 코드가 길어질수록 화면, 응답 로직, 설정, 대화 이력을 분리하면 필요한 부분만 수정하고 재사용하기 쉬워진다.

``` text
chatbot/
├─ app.py                 화면 구성과 전체 흐름
└─ common/
   ├─ ai.py               AI 응답 생성
   ├─ constants.py        역할과 설정값
   ├─ history.py          대화 이력 초기화·복원
   └─ show.py             메시지 출력·저장
```

### 1.1 화면과 실행 흐름

`app.py`는 Streamlit 화면을 만들고 다른 모듈의 함수를 조합한다.

``` python
import streamlit as st

from common.ai import get_msg_of_ai
from common.constants import ROLE
from common.history import init_history
from common.show import show_msg

st.title("ChatBot Service")
init_history()

user_input = st.chat_input("메시지를 입력해주세요.")
```

### 1.2 설정과 역할

API Key 같은 환경 설정과 사용자·도우미 역할처럼 여러 파일에서 공유하는 값은 별도 모듈에서 관리할 수 있다.

``` python
import enum

class ROLE(enum.Enum):
    user = enum.auto()
    assistant = enum.auto()
```

### 1.3 응답 로직과 화면 출력

응답 로직은 사용자의 입력과 이전 이력을 이용해 답변을 만들고, 화면 출력 함수는 역할에 맞는 채팅 메시지를 표시한다.

``` python
def get_response(user_input: str) -> str:
    return f"'{user_input}'에 대한 답변입니다."

def show_msg(role: ROLE, message: str) -> None:
    with st.chat_message(role.name):
        st.markdown(message)
```

> **핵심:** 화면은 입력과 출력에 집중하고, 응답 생성과 이력 관리는 별도 함수와 모듈에 맡긴다.

### 1.4 절대 import와 상대 import

```python
# app.py에서 패키지 경로를 기준으로 가져오기
from common.show import show_msg

# common/ai.py에서 현재 패키지의 모듈 가져오기
from .constants import ROLE
```

- 절대 import → 프로젝트의 패키지 경로를 처음부터 적는다.
- 상대 import → 현재 패키지를 기준으로 가져오며 `.`은 현재 패키지를 뜻한다.

## 2. Streamlit의 재실행과 세션 상태

Streamlit은 사용자가 값을 입력하거나 위젯을 조작하면 스크립트를 위에서부터 다시 실행할 수 있다. 일반 변수는 이 과정에서 다시 만들어지므로, 대화 기록처럼 계속 유지해야 하는 값은 `st.session_state`에 저장한다.

### 2.1 대화 이력 초기화

처음 실행할 때만 빈 리스트를 만들도록 키의 존재 여부를 확인한다.

``` python
if "history" not in st.session_state:
    st.session_state.history = []
```

매번 빈 리스트를 대입하면 기존 대화가 사라지므로 초기화 조건이 필요하다.

### 2.2 기존 대화 복원

스크립트가 다시 실행될 때 저장된 이력을 순서대로 화면에 다시 표시한다.

``` python
for history in st.session_state.history:
    show_msg(**history, is_history=True)
```

기존 메시지를 복원할 때 다시 이력에 추가하면 같은 메시지가 중복 저장될 수 있으므로, 복원 중에는 화면에만 출력한다.

### 2.3 새 메시지 저장

``` python
st.session_state.history.append({
    "role": ROLE.user,
    "msg": user_input
})
```

사용자 메시지와 챗봇 답변을 각각 한 번씩 저장하면 다음 재실행에서도 전체 대화를 복원할 수 있다.

> **핵심:** 세션 상태는 재실행 사이에 유지해야 하는 값을 저장하며 초기화·복원·추가 단계를 구분해야 한다.

## 3. Streamlit 채팅 UI

### 3.1 `st.chat_input()`

`st.chat_input()`은 채팅 메시지를 입력하는 위젯이다. 사용자가 메시지를 제출하면 문자열을 반환하고, 아직 입력하지 않았다면 조건문이 실행되지 않는다.

``` python
user_input = st.chat_input("메시지를 입력하세요.")

if user_input:
    st.write(user_input)
```

### 3.2 `st.chat_message()`

`st.chat_message()`는 역할에 맞는 채팅 메시지 영역을 만든다. `with` 블록 안에 `st.markdown()`을 배치하면 해당 역할의 메시지로 출력된다.

``` python
with st.chat_message("user"):
    st.markdown("안녕하세요")

with st.chat_message("assistant"):
    st.markdown("반갑습니다!")
```

- `user` → 사용자 메시지
- `assistant` → 챗봇 메시지

## 4. 챗봇의 전체 처리 흐름

사용자 입력은 화면, 세션 이력, 응답 생성 로직을 차례로 통과한다. 현재 입력이 AI 요청에 두 번 포함되지 않도록 이전 이력과 현재 입력을 구분한다.

``` text
저장된 대화 이력 초기화·복원
  ↓
st.chat_input()으로 새 메시지 입력
  ↓
이전 이력과 현재 입력으로 AI 요청 구성
  ↓
챗봇 답변 생성
  ↓
사용자 메시지와 답변을 각각 한 번 저장
  ↓
st.chat_message()로 화면 출력
```

``` python
if user_input:
    previous_messages = [
        {"role": item["role"].name, "content": item["msg"]}
        for item in st.session_state.history
    ]
    request_messages = previous_messages + [
        {"role": "user", "content": user_input}
    ]

    answer = request_ai(request_messages)
    show_msg(ROLE.user, user_input)
    show_msg(ROLE.assistant, answer)
```

실제 API 클라이언트처럼 생성 비용이 있는 자원은 `@st.cache_resource`를 적용한 함수에서 만들고 재사용할 수 있다. `.env`의 환경 변수는 `load_dotenv()`로 불러와 API 연결에 사용할 수 있다.

``` python
@st.cache_resource
def get_client():
    load_dotenv()
    return Groq()
```

> **핵심:** 현재 입력으로 답변을 만든 뒤 사용자와 챗봇 메시지를 한 번씩 저장하고 출력해야 대화 이력이 중복되지 않는다.

------------------------------------------------------------------------

## 5. UI와 로직을 분리하는 이유

역할을 나누면 화면 디자인을 바꿀 때는 `app.py`와 출력 모듈을, 답변 생성 방식을 바꿀 때는 `ai.py`를, 역할이나 설정값을 바꿀 때는 `constants.py`를 수정할 수 있다. 각 파일이 담당하는 책임이 분명하므로 코드의 재사용, 테스트, 유지보수가 쉬워진다.

같은 방식은 콘솔 가위바위보 실습에도 적용된다. 입력, 게임 규칙, 결과 출력, 실행 진입점을 서로 다른 파일로 나누고 `import`로 연결한다.

> **핵심:** 모듈화의 목적은 단순히 파일 수를 늘리는 것이 아니라 변경 이유가 다른 코드를 서로 분리하는 것이다.

## 전체 흐름

``` text
화면·응답·설정·이력 역할 분리
  ↓
session_state로 대화 이력 초기화·복원
  ↓
chat_input으로 현재 메시지 입력
  ↓
이전 이력과 현재 입력으로 답변 생성
  ↓
사용자와 챗봇 메시지를 한 번씩 저장
  ↓
chat_message로 대화 화면 구성
```

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| 모듈화 | 기능과 역할에 따라 코드를 파일로 분리 |
| 관심사 분리 | 화면·로직·설정·이력이 서로 다른 책임을 담당 |
| `st.session_state` | 재실행 사이에 유지할 데이터 저장 |
| 대화 이력 복원 | 저장된 메시지를 다시 화면에 표시 |
| `st.chat_input()` | 사용자 채팅 입력 위젯 |
| `st.chat_message()` | 역할별 채팅 메시지 영역 |
| `st.cache_resource` | API 클라이언트 같은 자원을 만들어 재사용 |

### 💻 주요 코드

| 코드 | 의미 |
| --- | --- |
| `from module import name` | 다른 모듈의 이름 가져오기 |
| `if "history" not in st.session_state` | 세션 이력 최초 초기화 |
| `st.session_state.history.append(...)` | 새 메시지 저장 |
| `st.chat_input(...)` | 채팅 입력창 생성 |
| `with st.chat_message(role)` | 역할별 메시지 영역 생성 |
| `@st.cache_resource` | 생성한 자원 캐시 |

### ⭐ 오늘의 핵심

- **역할 분리:** 화면, 응답 생성, 설정, 이력을 별도 모듈로 나누어 변경과 재사용을 쉽게 한다.
- **상태 유지:** 재실행되는 Streamlit에서 대화 기록은 `st.session_state`에 저장하고 기존 이력과 새 메시지를 구분한다.
- **채팅 흐름:** 입력, 응답 생성, 저장, 출력의 순서를 지켜 메시지를 중복 없이 관리한다.
