### 전이학습과 PyTorch 학습 흐름

사전학습 모델을 새로운 분류 문제에 사용할 때는 가중치에 맞는 전처리를 적용하고, 출력이 현재 클래스 수와 맞도록 분류기를 구성해야 한다. 학습 단계에서는 파라미터를 갱신하지만 평가 단계에서는 `eval()`과 `inference_mode()`를 사용해 모델의 상태를 바꾸지 않고 성능만 측정한다.

```text
사전학습 가중치와 전처리 준비
  ↓
현재 문제의 클래스 수에 맞는 분류기 구성
  ↓
학습 단계에서 가중치 갱신
  ↓
평가 단계에서 손실과 정확도 확인
  ↓
모델 상태 저장
```

> **핵심:** 모델·데이터·손실 함수가 서로 맞는지 확인한 뒤 학습과 평가의 역할을 분리한다.

## 1. 이미지 분류 프로젝트 모듈화

모듈화는 하나의 긴 학습 코드를 역할별 파일과 함수로 나누는 작업이다. 데이터 처리, 모델 생성, 학습, 실행 설정, 저장을 분리하면 한 부분을 바꿀 때 다른 부분에 미치는 영향을 줄일 수 있고, 필요한 기능을 다른 프로젝트에서도 재사용하기 쉽다.

| 파일 | 역할 |
| --- | --- |
| `data_setup.py` | 이미지 Dataset과 DataLoader 생성 |
| `model_builder.py` | 사전학습 모델과 새 분류기 구성 |
| `engine.py` | 한 에포크의 학습 단계와 평가 단계 수행 |
| `train.py` | 옵션을 받아 전체 학습 흐름 제어 |
| `utils.py` | 모델 저장과 같은 공통 기능 제공 |

### 1.1 데이터 로더 생성 분리

`create_dataloaders()`는 학습·평가 데이터 경로, 이미지 전처리, 배치 크기를 받아 두 DataLoader와 클래스 이름을 반환한다. 학습 데이터는 매 에포크마다 순서를 바꾸기 위해 `shuffle=True`를 사용하고, 평가 데이터는 결과를 안정적으로 확인하기 위해 `shuffle=False`를 사용한다.

```python
def create_dataloaders(train_dir, test_dir, transform, batch_size):
    train_dataset = datasets.ImageFolder(train_dir, transform=transform)
    test_dataset = datasets.ImageFolder(test_dir, transform=transform)

    train_loader = DataLoader(
        train_dataset, batch_size=batch_size, shuffle=True
    )
    test_loader = DataLoader(
        test_dataset, batch_size=batch_size, shuffle=False
    )

    return train_loader, test_loader, train_dataset.classes
```

MobileNet V3 Small의 사전학습 가중치를 사용하므로 전처리도 같은 가중치 객체가 제공하는 `MobileNet_V3_Small_Weights.DEFAULT.transforms()`를 적용한다. 사전학습 당시와 입력 크기·정규화 방식이 맞아야 학습된 특징을 올바르게 활용할 수 있다.

### 1.2 모델 구성 분리

실습 모델은 MobileNet V3 Small의 사전학습 파라미터를 동결하고, 기존 모델이 출력하는 1,000개 ImageNet logits 뒤에 현재 클래스 수를 출력하는 새 선형층을 연결한다.

```python
class MyModel(nn.Module):
    def __init__(self, target_size=3):
        super().__init__()
        self.pretrained_model = mobilenet_v3_small(
            weights=MobileNet_V3_Small_Weights.DEFAULT
        )

        for parameter in self.pretrained_model.parameters():
            parameter.requires_grad = False

        self.classifier = nn.Sequential(
            nn.ReLU(),
            nn.Linear(in_features=1000, out_features=target_size),
        )

    def forward(self, features):
        return self.classifier(self.pretrained_model(features))
```

배치 크기가 8이고 클래스가 3개라면 출력 logits의 형태는 `(8, 3)`, 정답 라벨의 형태는 `(8,)`가 된다. 출력의 두 번째 차원이 실제 클래스 수와 같은지 반드시 확인해야 한다.

> **핵심:** 실습 구조는 MobileNet 내부 분류층을 직접 교체하는 대신, 동결된 1,000개 출력 뒤에 `1000 → 클래스 수` 분류기를 추가한다.

## 2. 학습 단계와 평가 단계 분리

### 2.1 학습 단계

학습 단계는 모델을 `train()` 모드로 바꾸고 각 배치에서 예측, 손실 계산, 기울기 초기화, 역전파, 파라미터 갱신을 차례로 수행한다. 모델과 입력·정답 텐서는 모두 같은 장치에 있어야 한다.

```python
model.train()

for features, targets in dataloader:
    features = features.to(device)
    targets = targets.to(device)

    logits = model(features)
    loss = loss_fn(logits, targets)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

다중분류 logits에서 예측 클래스 번호만 필요하면 `logits.argmax(dim=1)`을 바로 사용할 수 있다. Softmax는 값을 확률로 바꾸지만 값의 크기 순서는 유지하므로, 최대값의 위치는 달라지지 않는다.

정확도는 맞힌 샘플 수를 전체 샘플 수로 나누어 계산한다.

```python
correct = 0
sample_count = 0

predicted = logits.argmax(dim=1)
correct += (predicted == targets).sum().item()
sample_count += targets.size(0)

accuracy = correct / sample_count
```

### 2.2 평가 단계

평가에서는 역전파와 파라미터 갱신을 하지 않는다. `eval()`은 Dropout과 Batch Normalization을 평가 방식으로 동작하게 하고, `inference_mode()`는 기울기 계산을 꺼 메모리 사용량과 연산량을 줄인다.

```python
model.eval()

with torch.inference_mode():
    for features, targets in dataloader:
        features = features.to(device)
        targets = targets.to(device)
        logits = model(features)
        loss = loss_fn(logits, targets)
```

배치별 손실을 더했다면 평균 손실은 DataLoader의 배치 수로 나눈다. 반면 정확도는 마지막 배치의 크기가 다를 수 있으므로 전체 샘플 수를 분모로 사용해야 한다.

### 2.3 전체 에포크 제어와 모델 저장

`execute_training()`은 학습 단계와 평가 단계를 에포크 수만큼 반복하고 손실과 정확도를 리스트에 기록한다. 학습이 끝나면 `state_dict()`를 저장해 나중에 같은 모델 구조에 불러올 수 있다.

```python
results = execute_training(
    model=model,
    train_dataloader=train_loader,
    test_dataloader=test_loader,
    optimizer=optimizer,
    loss_fn=torch.nn.CrossEntropyLoss(),
    epochs=args.epochs,
    device=device,
)

save_model(model, model_dir="models", model_name=args.model_save_path)
```

검증 성능이 일정 기간 개선되지 않으면 학습을 멈추는 Early Stopping을 추가할 수 있다. 이때 마지막 에포크의 모델이 아니라 검증 성능이 가장 좋았던 시점의 모델을 저장하는 것이 중요하다.

## 3. `argparse`로 실행 옵션 관리하기

`argparse`를 사용하면 배치 크기, 학습률, 에포크 수, 데이터 경로처럼 실험마다 달라지는 값을 코드를 고치지 않고 명령행에서 전달할 수 있다. 옵션을 생략했을 때 사용할 기본값과 입력 자료형도 함께 지정한다.

```python
parser = argparse.ArgumentParser(description="Train a PyTorch model.")
parser.add_argument("--batch_size", type=int, default=8)
parser.add_argument("--learning_rate", type=float, default=0.001)
parser.add_argument("--epochs", type=int, default=5)
args = parser.parse_args()
```

```shell
python train.py --batch_size 4 --epochs 8 --learning_rate 0.001
```

파싱한 값은 `args.batch_size`처럼 사용한다. 함수 호출에 필요한 설정을 딕셔너리로 모았다면 키 이름과 매개변수 이름을 맞춘 뒤 `function(**settings)` 형태로 한 번에 전달할 수도 있다.

> **핵심:** 코드와 실험 설정을 분리하면 같은 학습 코드를 여러 조건에서 반복 실행하기 쉽다.

## 4. `logging`으로 실행 상태 기록하기

`logging`은 메시지에 시간과 중요도를 붙이고, 설정한 수준 이상의 메시지만 선택해 보여 준다. 단순 출력인 `print()`와 달리 개발 중 상세 정보부터 심각한 오류까지 목적에 따라 구분할 수 있다.

| 로그 수준 | 용도 |
| --- | --- |
| `DEBUG` | 문제 원인을 찾기 위한 상세 정보 |
| `INFO` | 정상적인 실행 과정과 진행 정보 |
| `WARNING` | 주의가 필요하지만 계속 실행할 수 있는 상황 |
| `ERROR` | 작업 수행에 실패한 오류 |
| `CRITICAL` | 프로그램 전체에 영향을 주는 심각한 오류 |

```python
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s | %(levelname)s | %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S",
)

logging.info(f"Batch size: {args.batch_size}")
```

`INFO`로 설정하면 `INFO`보다 높은 `WARNING`, `ERROR`, `CRITICAL`도 함께 출력되고 `DEBUG`는 숨겨진다. 메시지를 지우지 않고 설정만 바꾸어 출력 범위를 조절할 수 있다.

## 5. TensorBoard로 학습 결과 시각화하기

TensorBoard는 학습 과정에서 기록한 손실과 정확도 같은 스칼라 값을 그래프로 보여 주는 도구다. 숫자 목록만 볼 때보다 학습 손실과 검증 손실의 변화, 정확도의 정체, 과적합 징후를 쉽게 확인할 수 있다.

### 5.1 값 기록하기

PyTorch에서는 `SummaryWriter`를 만들고 `add_scalar()`로 값을 기록한다. 기본 로그 디렉터리는 `runs/`이며, 기록을 마치면 writer를 닫아 파일을 정리한다.

```python
from torch.utils.tensorboard import SummaryWriter

writer = SummaryWriter()

for epoch in range(epochs):
    train_loss, train_acc = train_step(...)
    valid_loss, valid_acc = test_step(...)

    writer.add_scalar("Loss/train", train_loss, epoch)
    writer.add_scalar("Loss/valid", valid_loss, epoch)
    writer.add_scalar("Accuracy/train", train_acc, epoch)
    writer.add_scalar("Accuracy/valid", valid_acc, epoch)

writer.close()
```

`add_scalar(tag, scalar_value, global_step)`의 세 인자는 차례로 그래프 이름, 기록할 값, x축에 사용할 학습 단계를 뜻한다.

### 5.2 로그 확인하기

Jupyter Notebook에서는 TensorBoard 확장을 불러와 `runs` 폴더를 바로 확인할 수 있다.

```python
%load_ext tensorboard
%tensorboard --logdir=runs
```

실험마다 별도의 로그 폴더를 사용하면 배치 크기나 학습률이 다른 실행 결과를 비교할 수 있다. 학습 손실은 계속 감소하는데 검증 손실이 증가한다면 과적합 가능성을 점검하고, 두 손실이 모두 정체되면 학습률이나 모델 구조를 다시 살펴볼 수 있다.

### 💡 주요 개념

### 💻 주요 코드

| 코드 | 의미 |

| `weights.transforms()` | 사전학습 가중치에 맞는 전처리 생성 |

### ⭐ 오늘의 핵심

- **책임 분리:** 학습 프로젝트는 데이터, 모델, 한 에포크 처리, 전체 실행, 공통 기능을 나누면 수정과 재사용이 쉬워진다.
- **정확한 집계:** 평균 손실은 배치 기준, 정확도는 전체 샘플 기준으로 계산한다.
- **실험 관리:** `argparse`, `logging`, TensorBoard를 함께 사용하면 설정·진행 상태·결과를 체계적으로 관리할 수 있다.
